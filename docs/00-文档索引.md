## 5. V2.3 核验重点

- 当前实例是单管理员模型，没有多用户 RBAC。
- 原始会话及 Revision 仍是事实来源。
- 一个会话只有一个主项目，可有多个标签。
- 项目锁与人工/锁定标签在自动整理中受保护。
- “交还 AI 管理”会把标签关系真实切换为 auto，不再保留误导性的 manual 解锁状态。
- 搜索由可重建的消息分块覆盖完整历史，返回 Revision 与消息定位；`%`、`_` 按字面处理。
- 项目时间线选择最新完整 Revision，并通过统一分页显示全部结果。
- PROJECT-CONTEXT.md 可选智能总结或仅历史索引，智能失败时可回退。
- 周报/月报直接读取归档会话。
- Migration 当前到 0021；0019 新增二阶段 TOTP、设备健康、Revision 标题/URL、邮件状态和 Restore Job，0020 分离内容哈希、Revision 身份与内容完整性哈希，0021 固化 Restore 提交边界、恢复必需状态和暂存清理。
- Web 业务备份在一个 PostgreSQL REPEATABLE READ 快照中导出；支持只校验不恢复，并由 Restore Worker 分阶段恢复、重建检索和执行恢复后一致性检查。post-commit 异常保持维护模式直到恢复后处理成功。
- 实例时区以 `TZ` 为唯一口径，统一 Cron、报告周期、夜间任务键和 Web 日期筛选边界。
- Chrome Outbox 可查看、单条/全部重试和删除；401 明确进入 `AUTH_REVOKED`，保留队列等待重新配对。
- 设备页按客户端和 adapter 版本显示扫描、成功同步、失败码、成功率、部分率与连续失败。
- 系统状态支持归档完整性检查和全文检索重建；Release Qualification 与中文搜索基准脚本可独立运行。
- 认证、脱敏、网络和容器安全基线不变。
- Chrome 当前有 8 类网页适配器，不含豆包；豆包只存在于协议、历史导入和已有数据展示范围。
- 会话删除先进入 30 天回收站；用户可恢复或输入 DELETE 永久删除。

## 6. 已知实现边界

- Chrome 当前仍只有 8 类网页适配器，不含豆包。
- V2.3 之前的 Revision 没有可靠的历史标题/URL，明确标记 `metadataCaptured=false`；V2.3 起新 Revision 才可比较标题和地址变化。
- Restore 上传采用流式暂存和异步 Worker；Worker 当前仍会把单个备份解析到内存，压缩包 512 MiB、展开 1 GiB、单表 200 万行是硬限制。
- 全文检索的 GIN `tsvector` 对空格分词语言效果最好；中文等连续文本保留字面 ILIKE 回退。
- 8 个真实网页 DOM、Windows/macOS 安装、真实 SMTP/LLM、百万级中文搜索和完整灾备演练仍需目标环境 Release Qualification；代码不能替代现场验证。

完整问题和可信度见 [01-产品功能与业务规则](01-产品功能与业务规则.md) 第 11、12 节，不要用专题文档中的简写掩盖这些限制。

## 7. 发布核验命令

~~~powershell
pnpm typecheck
pnpm test
pnpm build
docker compose -f deploy/docker-compose.yml config
pnpm release:qualify
pnpm package:release
~~~

数据库迁移由 app 启动时执行，也可使用 `pnpm db:migrate` 手动运行。生产升级前必须先做数据库灾备与业务备份校验，并验证 `/healthz` 返回 V2.3.0。完整的发布门禁和现场留证要求见 [07-测试与质量保证](07-测试与质量保证.md)。
