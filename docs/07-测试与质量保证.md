## V2.4.7 本地验证记录（2026-10-25）

本次修复文件监听、Claude 损坏日志、gzip 读取竞态、队列重连、备份恢复内存预算、网页按需加载及搜索性能，更新存在已知问题的生产依赖，并保留旧版本 GUID 和 PATCH 字段语义。下列范围使用合成数据；既有生产数据与客户端配置未修改。

- Node.js 22.23.4，PostgreSQL 17 隔离容器；API 与项目 E2E 使用不同空库，各自应用当前 27 条迁移（0000–0026），全部通过并清理测试进程/容器。
- 真实 PostgreSQL 覆盖 7 个备份恢复场景：快照校验、事实恢复、搜索重建、提交前失败、损坏备份拒绝、持久化提交检查点后恢复、回执与归档完整性。提交边界故障使用注入中断，不等同于生产 Worker 断电演练。
- 真实 PostgreSQL 覆盖 15 个补采场景，包括并发租约、暂停恢复、失败重试、鉴权/回执关联、过期报告、取消及删除后不复活。
- 文件系统与 CLI 回归覆盖三类会话新增/追加、目录晚创建、敏感路径过滤、401 退出、损坏 Claude 增量回退，以及 gzip 读取/解压失败后的清理。
- 低堆真实 Node 进程（96 MiB）验证超出安全预算的压缩备份明确拒绝；格式上限保持不变，默认 512 MiB 容器不能据此承诺可恢复 1 GiB JSON。
- 网页首屏 JavaScript 从 638.84 kB 降至 401.33 kB；gzip 从 196.25 kB 降至 121.55 kB。Markdown 和版本历史按需加载，加载失败保留可读原文并可重试。
- 10,000 会话/100,000 消息与检索分块、每场景 30 次暖请求的合成库实测：稀有中文搜索 P95 从 1195.11 ms 降至 60.94 ms，无匹配搜索 P95 从 198.79 ms 降至 27.28 ms；摘要查询由逐结果读取改为批量读取，50 条结果的核心查询数从 55 降至 6。正文 trigram 索引额外约 7.64 MiB。频繁短词仍可能顺序扫描；结果不代表生产规模、冷缓存、并发或浏览器网络延迟。

## 4. 缺陷等级与准出标准

| 等级 | 定义 | 发布处理 |
| --- | --- | --- |
| P0 | 数据丢失、不可恢复损坏、认证绕过或生产不可用 | 必须修复并全量回归 |
| P1 | 核心流程错误、错误状态开放、可靠性恢复路径中断 | 必须修复并回归相关流程 |
| P2 | 有替代路径的功能或体验缺陷 | 评估后修复或明确进入后续版本 |
| P3 | 文案、样式或低风险工程改进 | 不阻断冻结，必须记录 |

发布准出要求：P0/P1 为零；自动化门禁全绿；迁移、备份和恢复证据完整；生产健康检查通过；仍未执行的外部平台项目必须在签字区明确承担风险，不能默认视为通过。
