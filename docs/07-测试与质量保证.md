## 1. 质量目标

| 目标 | 发布标准 |
| --- | --- |
| 归档正确性 | 不静默漏采；Revision 幂等、增量基线和事务边界符合业务规则 |
| 数据安全 | 迁移、备份与恢复可验证；提交后故障不得开放不完整搜索状态 |
| 安全性 | 认证、授权、同源、网络目标、文件上传、日志和密钥处理测试通过 |
| 可恢复性 | 入队失败、Worker 重启、过期任务和暂存文件均有明确恢复或清理路径 |
| 兼容性 | Chrome 八类 adapter 与 Windows/macOS 代理在目标版本通过实机验证 |
| 可维护性 | 类型检查、测试、构建、Compose、迁移、文档链接和发布包结构全部通过 |

## 4. 缺陷等级与准出标准

| 等级 | 定义 | 发布处理 |
| --- | --- | --- |
| P0 | 数据丢失、不可恢复损坏、认证绕过或生产不可用 | 必须修复并全量回归 |
| P1 | 核心流程错误、错误状态开放、可靠性恢复路径中断 | 必须修复并回归相关流程 |
| P2 | 有替代路径的功能或体验缺陷 | 评估后修复或明确进入后续版本 |
| P3 | 文案、样式或低风险工程改进 | 不阻断冻结，必须记录 |

发布准出要求：P0/P1 为零；自动化门禁全绿；迁移、备份和恢复证据完整；生产健康检查通过；仍未执行的外部平台项目必须在签字区明确承担风险，不能默认视为通过。

## 5. 冻结规则

- 发布候选版本：`V2.3.0`。
- 数据库迁移终点：`0022_tag_identity_hardening.sql`。
- 自动化门禁必须全部通过；任一失败即停止发布。
- 人工门禁必须在目标 NAS、浏览器、Windows、macOS、SMTP 和 LLM 环境完成；未执行项不得标记为通过。
- 恢复演练必须覆盖事实表事务提交前和提交后的 Worker 中断。提交后的失败必须进入 `recovery_required` 并持续维护模式，直到检索重建和完整性校验成功。
- 每次修复后至少重跑受影响检查；涉及迁移、备份、恢复、认证或采集时重跑全部自动化门禁。
