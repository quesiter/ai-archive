# 知言归藏 V2.1 用户手册

## 1. 产品用途

知言归藏把网页 AI 平台以及 OpenClaw、Codex、Claude Code 会话保存到自己的服务器，保留每次修订，并通过项目、标签、搜索和时间线找回历史。需要继续处理一个长期项目时，可以导出原始会话或生成 PROJECT-CONTEXT.md 交给外部 AI。

## 2. 初次使用

1. 按部署文档启动 app、worker、host-monitor 和 PostgreSQL。
2. 打开 Web，首次初始化管理员密码并把 TOTP 添加到认证器。
3. 登录后在“设备”创建配对码。
4. 在 Chrome 插件或 Windows/macOS 同步代理输入服务器地址和配对码。
5. 完成认领后再开始采集。

配对码一次性且短时有效。设备 Token 只在客户端显示，服务器仅保存哈希。

## 4. 采集与 Revision

插件在支持的平台页面识别当前会话。首次或结构变化较大时上传完整快照，后续可上传增量修订。同步代理扫描本地工具会话并持续上传。

会话详情的“版本”下拉可查看每次捕获。complete 表示检测完整，partial 表示内容可能尚未稳定或平台结构未完全识别。旧版本不会被新捕获覆盖。

## 5. 搜索历史

在“会话”输入关键词，系统同时搜索标题和消息正文。结果会标明“标题命中”或“正文命中”，正文结果显示附近摘要。点击后直接打开命中的 Revision 和消息。

可以组合：

- 平台与来源
- complete/partial
- full/append/import
- 起止时间
- 主项目
- 多个标签

多个标签采用 AND：选择 NAS 与 DDNS 时，只显示同时具有两个标签的会话。

## 6. 主项目

每条会话最多有一个主项目。项目用于长期主题，不适合为一次性问题单独建项目。

在会话详情选择项目后会人工锁定，自动整理不能改变。点击“交还 AI 调整”可解锁并重新整理。项目页可创建、编辑、归档和合并项目；合并不会删除原始会话、修订或标签。归档项目仍在独立区域保留会话、时间线、Context 和导出入口，也可以恢复，但归档期间不能接收新的人工归属。

## 7. 标签

标签用于更细的技术、产品、场景或问题维度。会话可以有多个标签。

在会话详情：

1. 输入或选择标签。
2. 点击新增；人工标签默认锁定。
3. 用锁按钮切换是否允许自动整理覆盖。
4. 用删除按钮只移除这条关联。
5. 点击标签名可查看所有使用该标签的会话。

在“项目与标签”的标签区可以搜索、创建、重命名、合并和删除。名称会自动处理首尾空格、全半角和大小写重复。删除标签不会删除任何会话。

## 8. 自动整理

“项目与标签”页可运行：

- 增量整理：处理新增、变化、未归类、低置信度或尚无标签的会话。
- 完整重评：重新检查全部会话。

AI 输出一个长期主项目和少量稳定标签。人工项目锁、人工标签和锁定标签受保护。遇 Token Plan 限制时，任务显示预计恢复时间并自动从断点续跑。

设置中可以控制采集后自动整理、项目变化后自动重评、节能/完整模式和稳定结果复用。每天 22:00 的夜间维护只运行增量整理；没有候选会话时立即结束。

## 9. 项目时间线

展开项目后加载“项目演进”。每项显示日期、平台、标题和标签，按最近捕获时间排列。点击项目时间线条目即可打开对应原始会话和 Revision。

时间线优先使用最新完整 Revision，不依赖 AI 生成一句概括，因此适合可靠追溯发生过的讨论。

## 10. 导出与 Project Context

会话和项目继续支持 CSV、Markdown、XLSX 原始导出。

在项目操作区点击“生成项目上下文”，浏览器下载 PROJECT-CONTEXT.md。内容包括项目说明、规模、主要标签、最近活动、历史索引、整体上下文和原始来源。它适合上传给 ChatGPT、Codex 或 Claude 恢复项目背景。

Context 只在点击时生成。若模型未配置，可关闭 AI 请求或先在设置中完成模型测试；确定性的历史索引和来源不依赖派生存储。

## 11. 周报与月报

周报按 Asia/Shanghai 统计上一完整周一 00:00 到本周一 00:00。月报使用完整自然月窗口。它们直接读取周期内变化会话的最新完整 Revision、项目、标签和必要正文；月报还可参考周报。

报告生成属于批处理，额度不足时会保存状态并延迟续跑。报告只保存为报告，不改变原始会话或项目标签。

## 12. 导入、备份与恢复

“导入”用于官方平台历史归档 ZIP。导入前会检查大小、路径、格式和重复数据。

“设置 → 备份与恢复”可下载 gzip JSON 备份并恢复。V2.1 备份包含标签关系。导入 V2.0.2 备份时，旧派生数据会被忽略并显示 warning；Conversation、Revision、Project、项目锁和 Report 继续恢复。如果旧备份没有标签，恢复后可手动运行一次项目与标签整理。

不同 APP_MASTER_KEY 的备份不会恢复加密密钥；需重新填写 API Key 和 SMTP 密码。

## 13. 安全建议

- 仅通过 HTTPS 暴露服务，不绕过反向代理。
- 妥善备份 APP_MASTER_KEY、数据库和 TOTP 恢复信息。
- 定期检查设备并撤销不用的 Token。
- 在设置中测试脱敏规则，再启动历史入库清理。
- 不把带凭据的日志、备份或 Context 上传到不可信位置。

## 14. 常见问题

“搜索不到正文”：确认会话已有 Revision，并清除过窄的平台、时间、项目或标签过滤。

“自动整理一直等待”：查看任务中的 retryAt/quotaResetAt 和 Worker 状态；不要重复创建相同任务。

“项目锁定后没有标签”：V2.1 的项目锁只锁项目。运行增量整理可补标签。

“Context 下载失败”：先检查项目是否有会话、模型设置是否可用，以及服务日志中的 interactive 请求错误。

“恢复旧备份出现 warning”：这是预期兼容行为，旧派生数据不会导入；原始归档和项目数据仍会恢复。
