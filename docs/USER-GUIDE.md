# 知言归藏用户手册

## 1. 首次登录

1. 部署服务后，在浏览器打开归档后台地址。
2. 第一次访问会进入初始化页面，创建管理员用户名和密码。
3. 系统会显示 TOTP Secret 和 OTP URI。
4. 用认证器 App 手工输入 Secret，或使用支持 URI 导入的方式添加 TOTP。
5. 后续登录需要输入用户名、密码和 6 位 TOTP。

注意：TOTP Secret 只在初始化时展示一次，请确认认证器可以正常生成验证码后再关闭页面。

## 3. 配对 Chrome 插件

在“设备”页面顶部可以直接下载 Chrome 扩展、Windows 电脑上传组件和 macOS 电脑上传组件。只有服务器发布目录中实际存在的包才会显示可下载按钮。

### 3.1 在后台生成配对码

1. 打开“设备”页面。
2. 创建配对码。
3. 设备类型选择 `Chrome 插件`。
4. 输入设备名称，例如“Windows Chrome”。
5. 复制生成的一次性配对码。

设备名称只在后台填写。插件侧只需要配对码。

### 3.2 在插件中输入配对码

1. 安装最新版 Chrome 插件。
2. 点击浏览器扩展图标。
3. 在插件弹窗中输入配对码。
4. 同意插件请求归档服务和支持 AI 平台的访问权限。
5. 配对成功后，插件会保存设备令牌。

插件包内已经固化归档服务地址。普通用户不需要在插件里输入服务器地址。

### 3.3 关于无痕模式和工具栏固定

当前插件 Manifest 声明 `incognito: "split"`，表示支持无痕窗口的独立运行上下文。但 Chrome 是否允许某个扩展在无痕模式运行，需要浏览器扩展管理页或企业策略授权。

Chrome 也不允许普通插件强制把自己固定到工具栏。固定按钮需要用户在浏览器扩展菜单中操作，或通过企业策略管理。

## 4. Chrome 自动采集如何工作

打开支持的 AI 会话页面后，插件会自动执行：

1. 判断当前域名是否在支持列表。
2. 匹配平台适配器。
3. 从 URL 或 QueryString 识别 Session ID。
4. 读取轻量指纹：消息数量、最后消息 ID、最后消息角色、最后消息正文指纹和流式状态。
5. 如果轻量指纹未变化，短暂显示“内容未变化”后回到待机，不扫描、不上传。
6. 如果是新会话或需要完整校验，扫描当前可见分支并生成完整快照。
7. 如果已有完整基线且只是新增回答，优先只解析新增消息并上传增量。
8. 上传到后台；网络失败时只重试 outbox，不重新扫描页面。

不需要手动点击“采集”。手动按钮主要用于重试或测试。

### 4.1 悬浮状态窗

插件会在支持的 AI 页面右上方贴边显示一个低干扰状态入口。状态变化：

| 状态 | 含义 |
| --- | --- |
| 待机 | 当前没有正在采集或上传。 |
| 检查变化 | 正在做轻量检查。 |
| 等待生成 | AI 仍在流式生成，暂不采集。 |
| 内容未变化 | 轻量指纹未变化，已跳过。 |
| 正在采集 | 正在扫描页面消息。 |
| 等待上传 | 快照已进入本地 outbox。 |
| 正在同步 | 正在上传到后台。 |
| 完整归档 | 服务端已保存完整快照。 |
| 部分归档 | 已保存，但无法证明完整性。 |
| 失败 | 页面识别、扫描或上传失败。 |

展开悬浮窗后可以：

1. 重试采集。
2. 暂停本站采集。
3. 恢复本站采集。

### 4.3 完整和部分的区别

完整归档必须证明：

1. 已扫描到会话顶部。
2. 已扫描到会话底部。
3. 页面内容已经稳定。

如果缺少任一证据，系统会标记为部分归档。部分归档仍会保存，但在报告和知识抽取中优先使用完整修订。

### 4.4 角色识别说明

插件优先靠页面结构识别角色，包括 DOM 属性、`data-testid`、类名、组件标签等。不是单纯按内容判断。

不同平台的可识别程度不同：

1. Grok 页面存在较明确的用户和 AI 标识，因此识别相对稳定。
2. 腾讯元宝、千问等页面如果缺少明确标记，插件会结合类名和消息容器判断，平台改版后可能需要更新适配器。
3. 如果某个平台只能识别 AI 消息或只能识别用户消息，通常说明该平台 DOM 结构变化或当前适配器选择器不足，需要看日志和 fixture 修复。

## 5. 使用会话列表

会话页面采用紧凑列表，适合几百条会话：

1. 使用搜索框搜索标题和消息正文。
2. 使用平台、来源、完整性、采集模式和时间范围筛选。
3. 搜索正文命中时，列表显示命中摘要，点击后尽量定位到命中消息。
4. 使用上一页、下一页翻页。
5. 点击一条会话进入详情。

会话详情中可以：

1. 查看当前修订消息。
2. 切换历史修订版本。
3. 查看来源设备、适配器版本、完整性、采集模式、触发原因、消息数量和采集时间。
4. 打开原始网页。
5. 设置或锁定项目。
6. 导出 CSV、Markdown 或 XLSX。
7. 删除该会话。

## 6. 管理项目和知识

### 6.1 创建项目

1. 打开“分类结果”页面。
2. 新建项目，填写名称和描述。
3. 项目名称应尽量使用真实项目名或主题名，便于本地匹配和 AI 分类。

### 6.2 手动锁定会话项目

在会话详情或项目相关区域中设置会话所属项目，并选择锁定。锁定后智能归类不会覆盖这个会话。

适合以下情况：

1. AI 分类反复不准。
2. 会话内容跨多个项目，但你明确希望归入某个项目。
3. 关键会话需要固定归属。

### 6.3 解除锁定并自动评估

如果希望系统重新评估，把会话项目设置回自动模式。系统会将该会话加入单会话归类队列。

### 6.4 查看知识

知识条目来自完整会话的 AI 抽取。每条知识包含：

1. 类型。
2. 标题。
3. 正文。
4. 置信度。
5. 来源会话、修订和消息序号。
6. 状态，例如有效、被替代、冲突、完成。

打开“项目知识”页面可按项目、知识类型和关键字过滤。点击“查看依据”会回到对应会话、修订和消息序号。点击“按新标准重建”会创建知识重建任务，页面显示总数、已处理、成功、失败和 Token Plan 等待状态。

### 6.5 合并与导出项目

在“分类结果”页选择源项目 A 和目标项目 B 后确认合并。系统会把 A 的会话、知识和相关报告迁移到 B，再删除 A；该操作不能在界面中撤销，执行前应先下载备份。每个项目可直接导出 CSV、Markdown 或 XLSX。

## 7. 智能归类

### 7.1 运行方式

打开“分类结果”页面，点击“智能归类”。默认选择“增量节能归类”，系统只会处理本轮候选会话：新会话、未归类会话、低置信度会话，以及最新修订晚于上次归类的会话。

运行后需要关注：

1. 任务是否进入队列。
2. 当前状态是排队、运行、完成还是失败。
3. 已处理数量和总数。
4. 本轮范围是增量候选还是完整重评。
5. 候选原因数量，例如未归类、低置信度、内容已更新。
6. AI 调用次数。
7. 本地命中数量。
8. 复用稳定结果数量。
9. 失败样本。

这些信息会显示在分类结果页和日志页中。

### 7.2 节能模式和完整模式

| 模式 | 说明 |
| --- | --- |
| 增量节能归类 | 默认日常模式。先在数据库筛出候选，再复用稳定结果、本地项目名匹配，必要时才调用 AI。适合 1200 条、几千条甚至更多会话的长期使用。 |
| 完整重评未锁定会话 | 强制重新评估未锁定会话。适合测试阶段、项目结构大改或分类明显错误时使用，不建议每天点。 |

如果你感觉“一次分类消耗了大量上下文”，优先使用增量节能归类，并适当降低 `classification.maxConversationChars`。完整重评会随总会话数增长而变慢，应该只在确实需要纠错或重建项目结构时使用。

### 7.3 推荐设置

| 设置 | 推荐值 | 说明 |
| --- | --- | --- |
| `classification.runMode` | `economy` | 日常使用更省上下文。 |
| `classification.reuseStable` | `true` | 避免重复分析已稳定分类。 |
| `classification.maxConversationChars` | `8000` | 当前默认值，长会话会截断。 |
| `classification.autoOnCapture` | 测试期可关闭 | 先确认适配稳定，再自动化。 |
| `classification.autoReclassify` | 测试期可关闭 | 自动重归类使用增量候选，测试阶段仍可先关闭，避免模型配置不稳定时反复入队。 |

### 7.4 Token Plan 调度与夜间维护

设置页默认启用 AI 请求节流，最小调用起始间隔为 82 秒，可按共享额度情况调整。MiniMax Token Plan 用完时，任务会显示额度窗口、刷新时间和倒计时；系统在刷新时间后再等待 10 分钟自动续跑，无法读取刷新时间时一小时后重试，不需要手工重新点击。

“每天 22:00 夜间维护”启用后，系统在 Asia/Shanghai 每晚 22:00 先执行增量智能归类，完成后再重建项目知识；仍在运行的同类任务会被复用，不会重复创建。

## 8. 生成周报和月报

模型配置只影响智能归类、知识抽取、周报和月报。没有配置 OpenAI 兼容模型时，Chrome 采集、本地同步、历史导入、会话列表、正文搜索、修订查看、导出和备份恢复仍然可以使用。

### 8.1 配置模型

1. 打开“设置”页面。
2. 填写 OpenAI 兼容接口：
   - Base URL
   - API Key
   - 模型名
3. 点击“测试”按钮。
4. 成功后再运行分类或报告。

### 8.2 立即生成报告

打开“报告”页面，点击：

1. 立即生成周报。
2. 立即生成月报。

点击后任务会进入队列。报告页的生成状态区只显示最新一次周报和最新一次月报，并展示状态、阶段、进度和错误；完整运行历史仍保留在日志中。

### 8.3 报告周期

| 类型 | 周期 |
| --- | --- |
| 周报 | Asia/Shanghai 时区下上一个完整周一至周日；标题和正文使用准确的起止日期。 |
| 月报 | Asia/Shanghai 时区下上一个完整自然月。 |

### 8.4 没有知识时的行为

如果当前没有可用于报告的知识，系统会生成本地占位报告，提示先完成采集、归类和知识抽取。这种情况不应再直接报模型字段缺失错误。单条会话知识抽取返回格式异常时，系统会在日志中记录 warning 并跳过该会话，继续处理本轮报告。

## 9. 历史导入

### 9.1 ChatGPT

1. 在 ChatGPT 中导出数据 ZIP。
2. 打开后台“导入”页面。
3. 上传 ZIP。
4. 查看导入页任务状态和日志页进度记录。

### 9.2 Gemini

1. 在 Google Takeout 选择 Gemini Apps 或相关活动数据。
2. 下载 ZIP。
3. 在后台“导入”页面上传。

### 9.3 Chat Memo

Chat Memo 导出的 ZIP 可以直接在后台“导入”页面上传。系统会识别其中的 ChatGPT、Gemini、腾讯元宝、DeepSeek、千问和豆包文本会话，并保留标题、原始 URL、消息时间和平台 Session ID。

同一 Session 的相同内容只保留一份；不同分支或内容版本会保存为新的 Revision。导入页的“未变”数量表示该快照已经存在，不是失败。

### 9.4 NAS inbox 投递

也可以把 ZIP 放入服务器配置的 `IMPORT_INBOX` 目录。Worker 每 5 分钟扫描一次并自动入队。

### 9.5 导入一直没有解析完成

排查顺序：

1. 打开“导入”页，看导入任务是否仍在排队、运行、重新入队或失败。
2. 打开“导入”页面，刷新会触发一次假死导入检查；如果 PgBoss 中没有对应活跃 job，系统会自动重新入队或标记失败。
3. 打开“日志”页面，筛选 `scope=import`。
4. 确认 Worker 容器正在运行。
5. 确认 ZIP 没有超过 2GB，且确实是 `.zip` 文件。
6. 确认 `IMPORT_INBOX`、`IMPORT_PROCESSED`、`IMPORT_FAILED` 目录对容器可写。

## 10. 系统备份与恢复

### 10.1 下载备份

打开“设置”页面，在“备份与恢复”面板点击“下载备份”。浏览器会下载一个 `.json.gz` 文件，里面包含当前业务数据。

Web 备份包含会话、修订、消息、项目、知识、报告、设备、设置、导入记录和操作日志；不包含管理员账号、登录会话和一次性配对码。

### 10.2 重建网站后导入

1. 按全新安装流程部署服务。
2. 首次访问后台，重新创建管理员账号并绑定 TOTP。
3. 打开“设置”页面，在“备份与恢复”面板选择备份文件。
4. 点击“导入备份并替换数据”。
5. 导入完成后检查会话、项目、报告和设备列表。

导入会替换当前业务数据，但会保留新站点的管理员账号。若重建时更换了 `APP_MASTER_KEY`，加密的 API Key/SMTP 密码会被跳过，导入后需要在设置页重新填写。

### 10.3 与脚本备份的区别

Web 备份适合“清空生产环境、重新部署网站、再把业务数据导回来”。`scripts/backup.sh` 仍适合 NAS 定时灾备，它生成 PostgreSQL dump，并建议连同 `deploy/.env` 一起保存。

### 10.4 安全脱敏规则

“设置 → 自定义脱敏规则”支持：

1. 一键启用密码、Authorization、数据库连接、SSH/SFTP、私钥和常见平台 Token 安全规则包。
2. 使用虚构文本预览数据库入库或发送 AI 前的脱敏结果；测试文本不会保存，也不会发给模型。
3. 启用、停用或删除单条规则。自定义规则不区分大小写，同时作用于发往 AI 的文本和后续采集入库。
4. 启动“清理已有归档”后台任务，清理消息正文、搜索索引、知识、报告和日志中的匹配内容。

数据库入库脱敏不可逆。不要把真实密码直接写进正则表达式；应该匹配字段结构，例如 `password\s*=\s*\S+`。系统用于调用模型和发送邮件的 API Key/SMTP 密码属于运行配置，会继续使用 `APP_MASTER_KEY` 加密保存。

### 10.5 查看系统状态

打开“设置 → 系统状态”。页面每 10 秒自动刷新，也可以点击“立即刷新”。

- “运行环境”显示应用服务、主机监测容器和 PostgreSQL 是否正常。
- “主机资源”显示 Uptime、Load、CPU、内存、Swap、归档数据所在磁盘和 inode，并保留最近 27 个 CPU/内存趋势点。
- 使用率达到 85% 时显示 Warning，达到 95% 时显示 Critical。若文件系统不提供可靠 inode 数据，页面会明确显示不可用，不会伪造百分比。
- “PostgreSQL”显示数据库大小、连接数、活跃连接、最长查询，以及通过 Web 下载备份产生的最近记录。

页面不保存长期监控历史。若主机指标显示不可用，先在 NAS 上运行 `docker compose --env-file .env ps`，确认 `host-monitor` 为 healthy；该容器不应映射到宿主机或公网端口。

## 11. 本地同步代理

### 11.1 在后台生成配对码

1. 打开“设备”页面。
2. 创建设备配对码。
3. 类型选择 `OpenClaw/Codex 同步代理`。
4. 名称填写运行代理的电脑，例如“MacBook OpenClaw”。
5. 设备侧只需要服务端地址和配对码，不输入设备名称。

### 11.2 在 MacBook 上配对并后台运行

在运行 OpenClaw、Codex 或 Claude Code 的 MacBook 上解压 macOS 同步包，双击 `AI-Archive-Sync.command`。

首次运行时输入后台生成的配对码。配对成功后脚本会询问是否安装后台同步，输入 `Y` 后会创建 macOS LaunchAgent，之后登录系统会自动隐藏运行。

如果之后需要重新安装、卸载或临时前台同步，再次双击 `AI-Archive-Sync.command`，按菜单选择对应操作。

### 11.3 Windows 上配对并后台运行

在 Windows 电脑上解压 Windows 同步包，双击 `sync-local-windows.bat`。首次运行时输入后台生成的配对码；配对成功后脚本会自动创建 Windows 计划任务，之后登录系统会自动隐藏运行。

如果之后需要重新安装或卸载后台同步：

```bat
sync-local-windows.bat install
sync-local-windows.bat uninstall
```

### 11.4 Codex 和 Claude Code 路径

Mac 和 Windows 的一键脚本都会默认读取 OpenClaw、Codex 和 Claude Code 的常见本地目录：

```text
~/.openclaw
~/.codex
~/.claude
```

Windows 对应为：

```text
%USERPROFILE%\.openclaw
%USERPROFILE%\.codex
%USERPROFILE%\.claude
```

如果路径不在默认位置，可以先设置环境变量再运行一键脚本：`AI_ARCHIVE_OPENCLAW_ROOT`、`AI_ARCHIVE_CODEX_ROOT`、`AI_ARCHIVE_CLAUDE_CODE_ROOT`。

Claude Code 的本地文件路径和 JSONL 事件字段可能随版本变化，因此该根目录是可配置的。解析器会保留可确认的用户、AI、system、tool 和 unknown 消息；损坏单行不会让整个文件失败；文件名包含 key、token、cookie、credential 的文件会被忽略。

### 11.5 同步行为

代理会：

1. 扫描本地会话文件。
2. 监听新增和变化。
3. 每 60 秒做轻量目录扫描。
4. 文件大小和 mtime 未变化时直接跳过。
5. 未压缩 JSONL 尾部增长时从上次 `readOffset` 后读取新增内容并上传增量。
6. 文件缩短、前部改写、压缩轮换或服务端基线不一致时完整解析。
7. 网络失败时不推进 offset，成功后记录本地 state。
8. 扫描过程中再次收到文件变化时，当前扫描结束后自动再扫描一次，避免遗漏仍在生成的 Codex 答案。
9. Codex 文件后续增长但 mtime 没变化时，使用本次实际观察时间记录新修订。

### 11.6 重新导入近期历史

需要重新核对近期本地文件时：

```sh
./AI-Archive-Sync.command rebuild
```

Windows：

```bat
sync-local-windows.bat rebuild-only
```

## 12. 日志排错

打开“日志”页面后，可以按范围筛选：

| 范围 | 适合排查 |
| --- | --- |
| `capture` | 插件采集失败、部分归档、元宝/千问识别错误。 |
| `classification` | 智能归类未入队、任务失败、模型返回异常。 |
| `analysis` | 周报、月报失败或长时间运行。 |
| `device` | 配对码错误、设备撤销、设备重命名。 |
| `import` | ZIP 重复、导入失败、解析异常。 |
| `system` | 系统级事件。 |

常用排查方式：

1. 先看对应业务页面是否有排队、运行或失败状态，再看日志页错误。
2. 再到日志页筛选对应范围。
3. 如果是报告或分类，检查设置页的模型测试是否成功。
4. 如果是采集，检查插件悬浮窗状态和当前 URL 是否有稳定 Session ID。
5. 如果是导入，检查 Worker 是否运行。

## 13. 常见问题

### 13.1 元宝总被识别成同一个会话

元宝 URL 中 `/chat/` 后面有两段。系统必须把两段组合成会话 ID。如果仍然只识别第一段，说明当前运行的插件不是最新版或构建包未更新。

### 13.2 千问识别不到人的消息

通常是页面 DOM 结构和当前适配器不一致。先看插件悬浮窗是否报部分或失败，再到日志页筛选 `capture`。如果页面中没有明确用户消息标记，需要更新适配器选择器和 fixture。

### 13.3 点了智能归类不知道有没有运行

看“项目”页的分类任务。应能看到排队、运行、进度、统计和失败样本。如果没有任务，检查日志 `scope=classification`。

### 13.4 周报或月报失败，提示字段缺失

当前版本已做模型输出容错。先确认 NAS 上运行的是最新版服务端，再到“设置”里测试模型。如果任务仍失败，打开日志筛选 `scope=analysis level=error`。

### 13.5 分类一次消耗过大

把分类模式设为节能模式，开启稳定结果复用，并降低最大会话字符数。测试阶段也可以关闭采集后自动分类和自动重归类，改为手动运行。

### 13.6 Codex 只显示问题，没有答案

先查看会话详情的版本下拉。旧版中 Codex 可能连续写入多个 `capturedAt` 相同的修订，页面因并列排序选择了最早修订；答案其实已经存在于后续修订。升级服务端和同步代理到 `V260822-4` 后，页面会按修订创建时间稳定选择最新完整版本，客户端也不会丢弃扫描期间收到的变化。升级后在 Windows 运行 `sync-local-windows.bat rebuild-only`，或在 macOS 选择近期历史重建，以补齐近期会话。
