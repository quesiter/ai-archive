## 1. 产品定位与用户

知言归藏是面向个人或小型自托管场景的 AI 会话归档、历史检索与项目演进系统。系统把网页 AI、OpenClaw、Codex、Claude Code 和历史导出包中的每个会话保存为一份持续积累的正文，再提供搜索、项目、标签、时间线、导出、报告、备份和运行监控。

当前实例只有一个 Web 管理员，没有团队成员、套餐、租户或细粒度 RBAC。Chrome 扩展、本地同步代理和协议中预留的 `importer` 以设备身份工作；设备只有有效、已撤销和已删除状态，不具备 Web 管理权限。

核心链路：

网页/本地文件/历史 ZIP → 设备认证或 Web 上传 → 脱敏与幂等采集 → Conversation/Revision 归档 → 项目与标签 → 搜索、时间线、导出与报告。

## 2. 当前产品边界

系统负责保存、组织、检索、追溯、导出和运维，不承担任务管理、日历、提醒、审批流、独立聊天、支付或团队协作，也不保存从会话拆出的长期知识实体。

已实现边界：

- Chrome 网页采集当前适配 ChatGPT、Gemini、Grok、腾讯元宝、豆包、MiniMax、DeepSeek、千问和 Kimi，包含豆包域名权限和新旧 DOM 适配。
- 本地同步代理只读扫描 OpenClaw、Codex、Claude Code、Grok Build CLI/Desktop 会话文件。
- Codex 子代理以原始父 ID 归组，主列表、项目时间线、首页/项目会话数量及待归类按主入口展示；子代理项目/搜索命中提升到所属主入口，子代理各自保留独立正文和身份。
- 代理升级自动只读全部历史 session_meta 头部回填已有归档关系，不受正文年龄、文件数量和文件大小窗口限制；无需重置状态，不创建未归档会话或复活已删除记录，同标题、同目录和用户主动 fork 不合并。
- 完整采集、追加增量和历史导入合并到同一累计正文；相同内容及重复请求保持幂等。
- 会话删除先写 `deletedAt` 进入 30 天回收站；支持恢复和输入 `DELETE` 后永久删除，Worker 自动清理到期记录。
- 支持 CSV、Markdown、XLSX 原始会话导出、Project Context、周报/月报、ZIP 历史导入、Web 业务备份恢复、设备管理、操作日志和系统状态。
- 没有 Webhook、短信、站内消息、Redis、外部全文检索或对象存储集成。

## 3. 身份与访问控制

- 首次初始化创建唯一管理员，用户名 3–64 字符、密码 12–256 字符，同时返回 TOTP Secret/URI；初始化不会自动登录。
- 登录需要用户名、密码和 6 位 TOTP。密码使用 Argon2id；TOTP 为 30 秒周期并允许前后一个窗口。
- Web Session 有效期 90 天，持续使用时每日自动续期，Cookie 为 HttpOnly、SameSite=Lax、Max-Age，生产环境 Secure。
- Web 写请求必须同源；公开接口仅限健康检查、认证状态、初始化、登录和设备认领。
- 设备通过 10 分钟有效的一次性配对码领取 Bearer Token，服务器只保存 Token 哈希。
- 系统没有创建第二个用户或角色分配；唯一管理员可以修改密码、重新绑定 TOTP、查看 Session、注销指定或其他浏览器 Session。
- TOTP 重绑采用两阶段切换：先创建限时 pending Secret，再用新验证码确认；确认前旧 Secret 始终有效。拥有服务器 Shell、数据库连接和 `APP_MASTER_KEY` 的运维者可使用恢复 CLI 重置密码/TOTP或注销全部 Session。

## 4. 会话、累计正文与采集

- Conversation 以 `provider + externalSessionId` 唯一；每个会话保存一份持续更新的 canonical Revision，采集片段没有再次出现的旧消息仍保留。
- 同 ID 的差异正文保存在 `mergeEvidence`，顺序无法确认时保留证据并标记待核对；普通任务、子代理和用户主动 fork 不因同名或同目录而合并。
- CaptureRun 以请求身份和不可变回执保证重试幂等；正文更新保持 canonical Revision ID 稳定，保留匹配消息的 ID 和首次入库时间。
- 追加必须匹配当前 `baseContentHash`、基线 Revision、消息数及末消息指纹；不匹配返回 `incremental_base_mismatch` 并回退完整采集。
- 主列表、搜索、项目时间线和导出读取同一累计正文；完整采集可提供新的顺序证据，但不据较短快照删除已保存内容。
- `complete` 表示采集时页面当前分支内容已全部读取，需要采集边界、加载稳定性和归档连续性成立；不要求 AI 回答结束或具有完整问答轮次。源回答未完成仅保留来源说明；漏采或无法读取内容时保存为 `partial` 并记录原因。回执区分本次来源条数/完整性与累计归档条数/完整性。
- 消息和 Segment 在入库前执行内置与自定义脱敏；推理、工具和内部运行时内容仍可归档，但 Web 详情和原始导出会按显示规则隐藏部分内部内容。
- 单 Segment 协议上限 2,000,000 字符；新采集入库还会对普通文本、推理和工具内容使用更低的截断上限。已经保存的历史正文在归并或重写时不再次应用当前截断和脱敏策略。

## 5. 搜索与详情

会话列表支持：

- 标题/正文关键词，最长 500 字符。
- 平台、来源、完整性、采集模式、主项目、最多 20 个标签、起止时间。
- 多标签 AND 过滤；起始时间包含、结束时间不包含。
- `limit` 1–200、`offset` 非负；列表统一返回 `items` 和含 total/limit/offset/hasMore 的 pagination，Web 使用统一分页组件。

正文搜索返回命中 Revision、消息序号和摘要，Web 打开详情后定位到消息锚点。完整消息正文写入可重建的 `conversation_search_chunks`；英文等分词文本使用 GIN tsvector，连续文本保留字面 ILIKE 回退。

详情显示累计消息、最近采集、归档状态和默认折叠的其他采集内容；支持打开原会话、项目分配、标签关联、CSV/Markdown/XLSX 导出和移入回收站。页面不再切换或比较历史版本，旧版本链接打开统一正文。非法 UUID 返回 400，不存在返回 404。

## 6. 项目

- 一个会话最多有一个主项目；项目名称 1–200 字符且数据库唯一，描述最长 5,000 字符。
- 管理员可创建、编辑、归档、恢复和合并项目，并可给会话人工指定或释放项目锁。
- 项目统计、项目列表、选择器和未归类会话分离；项目与未归类列表使用统一分页，不再由 overview 返回全部关系。
- 归档不会删除项目或已有关系；归档项目仍可查看会话、时间线、导出和生成 Context，但不能接收新的人工归属，也不会成为 AI 新归类目标。
- 合并在事务和项目级 advisory lock 中移动会话关系及报告引用，然后删除源项目；操作不可撤销。
- 项目时间线后端和 Web 均支持完整 `limit/offset` 分页。
- `POST /projects/:id/context` 支持 `{ai:true|false}`；Web 同时提供智能版和仅历史索引版，智能版失败时会询问是否降级确定性输出。

## 7. 标签

- 一个会话可关联多个标签。标签名称 1–100 字符，经过 NFKC、空白折叠、汉字与拉丁字母/数字边界空格消除和大小写归一后唯一；合并重复身份时不得丢失人工来源、锁定状态或较高置信度。
- 标签支持创建、搜索、重命名、合并、删除和按标签查看会话；删除标签只级联删除标签关系，不删除会话。
- 人工添加标签时 `source=manual`、`confidence=1`，默认锁定。
- 自动整理保留 `source=manual` 或 `lockedByUser=true` 的关系。
- “交还 AI 管理”会同时设置 `lockedByUser=false`、`source=auto`、清空人工 confidence，并触发单会话整理。

## 8. AI 自动整理

- 单次输出一个项目建议和最多 10 个标签建议；自动标签会经过可复用性、长度、数量和置信度校验。
- 增量整理处理未归类、低置信度、修订变化或缺少 V2.1 标签的会话；完整重评由用户显式触发。
- 项目锁只保护项目值，不阻止补充标签；人工或锁定标签不被自动覆盖。
- 新采集自动整理、项目变更自动重评、每周日 06:15 增量整理和每天 22:00 夜间维护均由设置开关控制。
- 批处理任务固定候选 ID 与 offset，支持额度窗口延迟续跑；同一时刻只复用/追踪一个批量整理任务。
- LLM 不可用时保留有效旧归属或保持待归类，不以通用技术词猜测项目；归档、搜索和原始导出不依赖 LLM。

## 9. 报告与邮件

- 周报窗口为实例 `TZ` 的上一个完整周一 00:00 到本周一 00:00；月报为该时区上一个完整自然月；Cron、夜间 runKey、Web 日期边界使用同一口径。
- 报告按窗口内采集活动选择会话，读取其累计正文并保留完整性说明；材料限于截止时间前首次入库的消息，并关联项目、标签和有限正文。月报可引用窗口内周报。
- 报告保存于 `reports`，不会反写原始会话或项目标签。
- Web 可手动创建周报/月报并分页查看全部报告；报告可下载 Markdown，但不能编辑或删除。
- Worker 可按周一 07:30、每月 1 日 08:00 自动生成，并通过 SMTP 发送完整报告正文和详情链接。
- Report 记录邮件 queued/sent/failed/not_configured、attempt、发送时间和错误；失败邮件可从 Web 重试。
- 采集活动窗口统一使用 `[windowStart, windowEnd)`，相邻周期不会重复包含右边界活动。

## 10. 导入、备份与恢复

- Web 接受最大 512 MiB 的 ZIP；Worker 识别 ChatGPT 官方导出、Gemini Takeout 和 Chat Memo ZIP，并限制路径、条目数、单条目及总展开大小。
- 相同 ZIP 文件哈希只创建一个 ImportJob；单个快照事务化保存，但整个 ZIP 不是一个数据库事务，部分成功后失败不会整体回滚。
- Worker 启动和每 5 分钟扫描 Import Inbox；失去活跃队列任务的 processing 记录会根据源文件存在与否重试或失败。
- Web 业务备份在一个 PostgreSQL REPEATABLE READ 只读快照中流式 gzip 导出 18 张业务表，不含 users、web_sessions、pairing_codes、派生检索分块和 PgBoss 内部表。
- 管理员可只验证备份的 gzip、格式、Schema、18表、引用、Delta基线、计数和主密钥指纹，不写数据库。
- Web 恢复先流式上传到 app/worker 共享且可写的 staging，返回202和 RestoreJob；Worker 分阶段校验、事务替换、重建搜索和检查完整性。事务提交前失败整体回滚并可完整重试；提交后失败进入 recovery_required 并保持维护模式，重试只重建搜索和验证。failed文件按配置保留并可手动删除。
- 主密钥指纹不同会跳过加密设置；旧 knowledge 数据和任务被忽略并返回 warning。
- PostgreSQL 运维备份/恢复与 Web 业务备份是两套不同机制。

## 11. Dashboard、日志、系统状态与导航

当前主导航固定为：总览、会话、活动、项目、标签、报告、导入、设备、日志、回收站、设置；更新记录位于侧栏底部。旧 `/classification` 重定向到 `/projects`，未知路径重定向首页。

Dashboard 展示会话、完整性、项目/标签、文本量、Token 估算、设备、近期增长、采集健康、活跃项目和报告。Token 值混合使用来源上报与文本估算，不是计费账单。

日志支持 1h/24h/7d/30d、自定义日期、范围、级别、状态、平台、设备、关键词和 offset 分页。设备页显示客户端版本/OS/扫描/同步/错误，并按 provider+adapterVersion 展示 24h/7d Adapter Health。系统状态提供搜索重建和归档完整性检查；`/api/v1/activity` 已有分页 Web 页面。

## 12. 安全与部署要求

- 生产必须使用 32 字节 Base64 `APP_MASTER_KEY`；非本机 `APP_ORIGIN` 必须 HTTPS。
- LLM 与 SMTP 默认拒绝回环、私网、链路本地、元数据和保留地址；只有显式启用 `ALLOW_PRIVATE_NETWORK_TARGETS` 才可访问可信内网目标。
- 动态响应 `Cache-Control: no-store`，生产启用 HSTS，并设置 CSP、COOP 和 Permissions Policy。
- app、worker、host-monitor 以非 root、只读根文件系统、`no-new-privileges` 和 capability drop 运行。
- 自定义脱敏正则必须通过安全检查；历史归档脱敏不可逆，执行前必须备份。

## 13. 验收与已知限制

验收时至少确认：

- 单管理员初始化、TOTP 登录、设备配对和撤销正常。
- Chrome 8 个当前适配平台与三种本地文件来源分别可完成完整/增量采集。
- Revision、搜索定位、项目/标签、导出、报告、导入和备份恢复形成闭环。
- Migration 0000–0024 可从支持的旧库顺序执行；0012 删除旧 knowledge 表，0016–0022 建立归档、搜索、账号、恢复和标签治理，0023 保存父子关系，0024 增加累计归档标记、差异证据和不可变采集回执。历史正文归并在完整备份后单独执行并验证内容保留。
- `pnpm typecheck`、`pnpm test`、`pnpm build`、Compose 配置和运行中 E2E API 检查通过。

当前需保留为已知限制的事项：豆包登录态长会话、真实9站DOM、Windows/macOS安装、SMTP/LLM、多Worker和百万级中文搜索仍需发布环境验证；Restore Worker 仍把受限大小的 staged 备份/解压 JSON 读入内存；完整性检查只诊断、不猜测修复事实档案。

发布验收通过 `pnpm release:qualify` 汇总类型检查、测试、构建和可选 E2E，并单列真实 Chrome、Windows/macOS、SMTP、LLM、恢复演练等人工门禁；搜索性能通过 server 的 `benchmark:search` 输出 P50/P95/P99 与 EXPLAIN JSON。
