# 知言归藏 V2.1 需求基线

## 1. 产品定位

知言归藏是个人自托管的 AI 会话归档、历史检索与项目演进系统。系统保存跨平台 AI 会话及其修订，以原始 Conversation、Revision、Message 为唯一事实来源，并提供项目与标签组织、搜索、时间线、项目上下文导出、周报和月报。

核心链路：

跨平台会话 → 可靠采集 → 版本化归档 → 项目与标签 → 搜索与追溯 → Context 导出 → 外部 AI 再利用。

## 2. 产品边界

V2.1 只负责保存、组织、检索、追溯和导出，不承担任务管理、日历、提醒、工作流或独立聊天助手。系统不保存从会话拆出的长期知识实体，不运行知识抽取或知识重建任务。

必须保持：

- Chrome 网页采集和 OpenClaw、Codex、Claude Code 本地同步。
- 完整与增量修订、幂等、软删除及永久删除。
- 原始会话 CSV、Markdown、XLSX 导出。
- 周报、月报、备份恢复、设备管理、操作日志和运行状态。
- 现有认证、网络、脱敏、容器安全基线。

## 3. 会话与修订

- Conversation 表示稳定会话身份；Revision 表示一次捕获状态。
- 完整修订优先用于搜索、分类、时间线、报告与 Context。
- 新修订不得覆盖旧修订；相同内容快照保持幂等。
- 原始消息内容不因项目、标签或 AI 整理而变化。
- 会话详情必须能选择修订，并通过消息序号定位命中消息。

## 4. 项目

- 一个会话最多有一个主项目。
- 项目表示长期项目或粗主题，禁止把一次性问题或整句话当项目名。
- 自动整理优先复用现有项目；置信度不足时保留待归类或建议名。
- 用户可人工指定、锁定和解锁主项目。
- 人工项目锁只阻止自动更改项目，不阻止为该会话补充标签。
- 项目支持创建、编辑、归档、合并和原始会话导出。
- 合并只移动项目关系与报告引用，不改变 Conversation、Revision、Message 和 Tag。

## 5. 标签

- 一个会话可关联多个标签。
- 标签按 NFKC、空白折叠和不区分大小写的 normalizedName 唯一。
- 自动标签通常 2～8 个，最多保留 10 个；低置信度、整句式和不可复用标签应被过滤。
- AI 优先复用已有标签并避免同义词膨胀。
- conversation_tags 保存 confidence、source、lockedByUser 和时间戳；source 仅为 auto 或 manual。
- 人工新增标签默认锁定；人工或锁定关系不得被自动整理覆盖。
- 标签支持搜索、创建、重命名、合并和删除；删除仅删除关联，不删除会话。
- 会话列表支持多个标签的 AND 组合过滤。

## 6. 智能整理与调度

AI 单次输出一个项目建议和多个标签建议。提交给模型的会话文本必须经过现有云端脱敏链路。

- 增量整理处理未归类、低置信度、修订变化或尚无 V2.1 标签的会话。
- 完整重评由用户显式触发。
- 节能模式可复用稳定且已有标签的结果。
- 项目锁定时仍可生成标签，但项目值保持不变。
- 夜间维护仅运行增量项目与标签整理；无候选时立即结束。
- Batch 调用使用低优先级节流；用户主动生成 Context 使用 interactive 优先级。
- Token Plan、retryAt、quotaResetAt、延迟续跑和失败容错继续生效。

## 7. 搜索

会话搜索必须支持标题和正文，并可组合以下过滤条件：

- 项目
- 一个或多个标签
- 平台
- 来源
- 完整性
- Capture Mode
- 时间范围

结果显示“标题命中”或“正文命中”和附近摘要。正文命中链接必须携带 conversationId、revisionId 和 message ordinal，使用户直接打开对应原始消息。

## 8. 项目时间线

- 时间线按项目列出日期、平台、会话标题和标签。
- 每项链接回原始会话与选中的修订。
- 每个会话选择最新完整修订；如时间相同，以 createdAt 和 id 稳定决胜。
- 不为每项强制生成 AI 摘要。

## 9. 项目 Context

用户可按需生成并下载 PROJECT-CONTEXT.md。文件包含项目说明、会话规模、主要标签、最近活动、历史讨论索引、当前项目上下文和原始来源链接。

- Context 是项目级整体材料，不拆成长期知识实体。
- 默认允许 interactive AI 生成整体叙述；原始索引和来源始终由数据库确定性生成。
- 不在每次采集后自动生成，也不建立后台定时重建。

## 10. 报告

- 周报窗口为 Asia/Shanghai 上一完整周一 00:00 至本周一 00:00。
- 周报直接读取周期内每个会话的最新完整修订、项目、标签及必要正文。
- 月报直接读取当月会话、项目、标签、周报及必要历史对比。
- 报告内容只保存在 Report，不反写派生实体。
- 周报、月报必须在旧知识表已删除的数据库上正常运行并支持额度延迟续跑。

## 11. Dashboard 与导航

主导航固定为：总览、会话、项目与标签、报告、导入、设备、日志、设置；更新记录位于侧栏底部。

Dashboard 展示总会话、总项目、已归类、未归类、标签数、文本量、估算 Token、活跃设备、近 7 日新增、近 24 小时采集健康、最近活跃项目和最近报告。

## 12. 数据迁移与备份

V2.0.2 升级到 V2.1 必须：

- 创建 tags 与 conversation_tags。
- 删除旧 knowledge_items 表及其索引和约束。
- 清理旧 knowledge_rebuild 任务，使新 Worker 不会尝试执行。
- 完整保留 Conversation、Revision、Message、Project、人工项目锁和 Report。
- 不把旧派生数据转换成 Tag；标签必须以后从原始会话重新判断。

新备份包含 tags 和 conversationTags，不包含旧派生表。旧备份允许 knowledgeItems 或 knowledge_items，恢复时忽略并返回中文 warning；没有标签数据时按空标签恢复。

## 13. 安全与部署

不得削弱 TOTP、Cookie Session、设备 Bearer Token、Token Hash、APP_MASTER_KEY、HTTPS、HSTS、CSP、SSRF 与 DNS Rebinding 防护、入库脱敏、LLM 前二次脱敏、敏感日志过滤，以及容器的非 root、只读文件系统、no-new-privileges 和 capability drop。

## 14. 验收

- 当前 UI、API、schema、worker 和任务队列不存在旧派生主链路。
- Conversation 能表达一个主项目和多个标签。
- 搜索可按项目、标签、关键词、平台和时间定位原始消息。
- 项目页面显示基本信息、标签分布、会话、时间线、最近变化和导出入口。
- 用户可下载 PROJECT-CONTEXT.md。
- 报告直接基于归档会话。
- V2.0.2 业务数据和旧备份可安全升级或恢复。
- TypeScript、全部自动化测试、生产构建、迁移检查、Compose 检查和文档链接检查通过。
