# 知言归藏项目需求文档

## 1. 背景

用户在 ChatGPT、Gemini、Grok、腾讯元宝、MiniMax Agent、DeepSeek、千问、Kimi、OpenClaw、Codex、Claude Code 等工具中持续产生大量 AI 会话。这些会话分散在多个第三方账号、多个浏览器和多台设备中，平台自身的搜索、导出和长期检索能力不一致，也不适合作为个人长期会话数据库。

“知言归藏”的首要目标是把不同来源的 AI 会话归档到用户自托管的 NAS 或本地服务中。项目归类、知识抽取、周报和月报属于可选辅助能力，不得阻塞采集、归档、搜索、导出和修订查看。

## 2. 产品目标

1. 自动归档多个 AI 平台的会话内容，尽量减少手动点击。
2. 用统一数据结构保存会话、消息、分段、版本、来源设备和采集完整性。
3. 保证会话列表、搜索、修订查看和来源追踪在没有配置模型时也可用。
4. 让采集、导入、归类、报告等异步任务的状态可见、可追踪、可排错。
5. 默认保护隐私；采集内容中的密码、密钥、私钥和登录信息在入库前不可逆脱敏，其他隐私字段在发往云端模型前继续脱敏。
6. 支持 NAS 长期运行，也支持本地开发、MacBook 上独立运行同步代理。

## 3. 用户角色

| 角色 | 说明 | 主要操作 |
| --- | --- | --- |
| 系统管理员 | 拥有 Web 后台账号和 TOTP，负责部署、配置和维护。 | 初始化账号、配置模型、SMTP、设备配对、升级、备份恢复、查看日志。 |
| 日常使用者 | 与管理员通常是同一人，主要消费归档和报告。 | 浏览会话、搜索内容、手动锁定项目、运行分类、查看知识和周/月报。 |
| 采集设备 | Chrome 插件、本地同步代理或导入器。 | 使用设备令牌上传会话快照、增量或导入任务。 |

## 4. 范围

### 4.1 当前支持

| 类型 | 支持范围 |
| --- | --- |
| 网页自动采集 | ChatGPT、Gemini、Grok、腾讯元宝、MiniMax Agent、DeepSeek、千问、Kimi。 |
| 本地会话同步 | OpenClaw Session JSONL、Codex sessions JSONL、Codex archived sessions、Codex session index 标题、Claude Code 可配置 JSONL 根目录。 |
| 历史导入 | ChatGPT 导出 ZIP、Gemini Takeout ZIP、Chat Memo 多平台 ZIP（已实现 ChatGPT、Gemini、元宝、DeepSeek、千问、豆包）。 |
| 管理后台 | 总览、会话、分类结果、项目知识、报告、导入、设备、日志、设置。 |
| AI 能力 | OpenAI 兼容接口测试、项目归类、知识抽取、周报、月报、知识状态合并。 |
| 运维能力 | Docker Compose 部署、数据库迁移、组件下载、Web 业务备份、PostgreSQL 备份/恢复脚本、健康检查、操作日志。 |

### 4.2 当前不承诺

1. 不直接抓取手机 App。本系统通过同账号网页同步后，在电脑浏览器打开会话补录。
2. 不保证采集平台隐藏推理、已删除消息、未访问分支、附件二进制内容和平台未同步的临时会话。
3. 不使用第三方平台 Cookie 或私有接口批量拉取。
4. 不强制 Chrome 插件默认固定到工具栏；固定行为由 Chrome 浏览器或企业策略控制。
5. Chrome 无痕模式是否启用由浏览器扩展设置控制。当前 Manifest 声明 `incognito: "split"`，但普通手动安装时仍需要浏览器允许扩展在无痕中运行。

## 5. 功能需求

### 5.1 账号与安全

| 编号 | 需求 |
| --- | --- |
| AUTH-001 | 首次访问后台时可以创建管理员账号。 |
| AUTH-002 | 管理员登录必须使用密码和 TOTP 二次验证。 |
| AUTH-003 | Web 后台使用 Cookie Session，设备上传使用 Bearer Token，两类凭据隔离。 |

| AUTH-005 | `APP_MASTER_KEY` 用于加密 TOTP、API Key、SMTP 密码等敏感配置。 |

### 5.2 设备配对

| 编号 | 需求 |
| --- | --- |
| DEVICE-001 | 后台可以创建一次性配对码，并指定设备名称和设备类型。 |
| DEVICE-002 | Chrome 插件侧和本地同步代理侧只输入配对码，不再输入设备名称。 |
| DEVICE-003 | 配对成功后，服务端签发设备 ID 和设备令牌。 |
| DEVICE-004 | 后台可以查看设备类型、名称、创建时间、最后在线时间和撤销状态。 |
| DEVICE-005 | 后台可以编辑已配对设备名称。 |
| DEVICE-006 | 第一次删除未撤销设备时执行撤销，撤销后再次删除可从列表中移除。 |
| DEVICE-007 | 设备页发现并下载发布目录中的 Chrome、Windows 和 macOS 采集组件，显示组件版本、大小和可用状态。 |

### 5.3 Chrome 网页自动采集

| 编号 | 需求 |
| --- | --- |
| CAP-001 | 插件在支持的 AI 网页中自动识别稳定会话 ID，识别到后自动采集，不要求用户手动点击。 |
| CAP-002 | 插件自动监听页面内容变更、路由变更和 Session ID 变化，但只触发轻量检查；确认有效变化后才进入正式采集。 |
| CAP-003 | 插件将采集结果写入本地 outbox，再压缩上传到服务端。网络失败时保留待重试。 |
| CAP-004 | 上传请求必须携带 `Idempotency-Key`，服务端用它减少重复写入。 |
| CAP-005 | 插件必须区分完整、部分和失败采集，不能把无法证明完整的页面误报为完整。 |
| CAP-006 | 完整采集需要同时满足到达顶部、到达底部、页面稳定三个证据。 |
| CAP-007 | 插件在网页右上方贴边显示低干扰悬浮状态入口，采集或上传时显示轻微状态变化。 |
| CAP-008 | 悬浮窗可以展开查看状态、重试和暂停本站采集。 |
| CAP-009 | 插件支持隐藏悬浮窗；隐藏状态保存在浏览器本地存储中。 |
| CAP-010 | 插件不能读取或上传第三方平台 Cookie。 |
| CAP-011 | 插件的定时器、路由轮询和 MutationObserver 只能触发轻量变化检查，不能在未变化时直接完整扫描。 |
| CAP-012 | 插件本地保存 `provider + sessionId + branchFingerprint` 级别状态，包含消息数量、最后消息 ID、最后消息角色、最后消息正文指纹、适配器版本和完整性。 |
| CAP-013 | 内容未变化时立即跳过，不滚动页面、不生成完整快照、不写 outbox、不上传、不写持久化未变化日志。 |
| CAP-014 | 已有完整基线且只追加新消息时，优先上传 `append` 增量；基线不一致时回退完整采集。 |

### 5.4 平台适配

| 编号 | 需求 |
| --- | --- |
| ADAPTER-001 | 每个平台单独维护域名、会话 ID 规则、消息选择器、用户消息提示、AI 消息提示、推理分段、工具分段和流式生成标识。 |
| ADAPTER-002 | 角色识别优先依赖页面 DOM 标签、属性、组件名和 CSS 类名，不应只靠文本内容猜测。 |
| ADAPTER-003 | Grok 可利用 `data-testid` 等较明确标记区分用户和 AI 消息。 |
| ADAPTER-004 | 腾讯元宝会话 ID 必须使用 `/chat/<空间或账号段>/<会话段>` 两段组合，不能只取第一段。 |
| ADAPTER-005 | 千问同时支持 `qianwen.com` 与 `www.qianwen.com`，会话 URL 形如 `/chat/<id>` 或 `/conversation/<id>`。 |
| ADAPTER-006 | 页面结构变化导致适配失败时，应记录失败或部分状态，避免产生错误完整归档。 |

| 编号 | 需求 |
| --- | --- |

| CONV-002 | 同一会话的不同采集结果以修订版本保存。 |

| CONV-004 | 每条消息保存角色、顺序号、外部消息 ID、模型、原始时间和分段。 |
| CONV-005 | 分段类型支持正文、推理、代码、引用和工具状态。 |
| CONV-006 | 会话详情可以切换不同修订版本。 |
| CONV-007 | 会话列表需要紧凑显示，支持搜索、平台过滤和分页，适合几百条会话。 |
| CONV-008 | 用户可以删除会话，当前实现为硬删除相关归档数据。 |
| CONV-009 | 会话列表支持来源类型、时间范围、完整性和采集模式筛选，显示最后同步时间、采集模式和来源设备。 |
| CONV-010 | 搜索正文命中时返回摘要和消息序号，点击结果尽量定位到命中消息。 |
| CONV-011 | 单条会话和整个项目可以导出为 CSV、Markdown 或 XLSX。 |
| CONV-012 | 选择最新修订时先考虑完整性，再按采集时间和修订创建时间稳定排序；多个 Codex 修订采集时间相同时不得让早期问题修订遮挡后续答案。 |

### 5.6 项目与知识

| 编号 | 需求 |
| --- | --- |
| PROJECT-001 | 用户可以创建、编辑和归档项目。 |
| PROJECT-002 | 每个会话最多关联一个项目。 |
| PROJECT-003 | 用户手动指定项目时可以锁定，后续智能归类不得覆盖。 |
| PROJECT-004 | 用户可以切回自动模式，让系统重新评估会话所属项目。 |
| PROJECT-005 | 系统从完整会话中抽取长期知识，类型包括决策、需求、事实、想法、任务、风险、资源和待解问题；标题与正文统一整理为简体中文，必要的产品名、代码标识符和协议名可以保留英文并用中文解释。 |
| PROJECT-006 | 每条知识必须引用来源会话、修订版本和消息序号。 |
| PROJECT-007 | 月报可更新知识状态，例如有效、被替代、冲突或完成。 |
| PROJECT-008 | 知识重建需要在项目范围内合并重复或互补条目，并过滤助手实施计划、工具进度、过程播报、临时状态、已完成的一次性任务和无证据猜测。 |
| PROJECT-009 | 用户可以把源项目合并到目标项目；系统迁移会话、知识和相关报告后删除源项目，并记录操作日志。 |
| PROJECT-010 | 项目知识页支持手动启动全量知识重建、显示任务进度，并按项目、类型和关键字过滤当前有效知识。 |

### 5.7 智能归类

| 编号 | 需求 |
| --- | --- |
| CLASS-001 | 后台提供“智能归类”入口，对未人工锁定的会话重新评估项目归属。 |
| CLASS-002 | 分类任务必须显示排队、运行、完成、失败、进度百分比、已处理数量和统计信息。 |
| CLASS-003 | 分类支持节能模式和完整模式。 |
| CLASS-004 | 节能模式优先复用稳定分类结果，避免反复消耗上下文和模型额度。 |
| CLASS-005 | 节能模式在调用 AI 前先做本地项目名匹配。 |
| CLASS-006 | 完整模式会强制重新评估未锁定会话，用于测试和纠偏。 |

| CLASS-009 | 所有 AI 模型调用共享可配置的全局起始间隔，默认 82 秒，以降低本系统对共享 Token Plan 的瞬时占用。 |
| CLASS-010 | Worker 每天 Asia/Shanghai 22:00 自动执行夜间维护，并按增量智能归类、项目知识分析的顺序串行衔接；已有任务不得重复创建。 |

### 5.8 报告

| 编号 | 需求 |
| --- | --- |
| REPORT-001 | 后台可以立即生成周报或月报。 |
| REPORT-002 | 周报窗口为 Asia/Shanghai 时区下上一个完整周一到周一。 |
| REPORT-003 | 月报窗口为 Asia/Shanghai 时区下上一个完整自然月。 |

| REPORT-005 | 月报基于已有知识做状态合并和项目演进总结。 |
| REPORT-006 | 报告生成过程必须在报告页展示阶段、进度、错误和完成结果。 |
| REPORT-007 | 模型返回 JSON 结构不完全一致时，系统应尽量做兼容解析和字段归一化。 |
| REPORT-008 | 没有可用知识时，系统应生成本地占位报告，而不是直接失败。 |
| REPORT-009 | 报告页的生成状态只展示最新一次周报和最新一次月报；周报必须明确显示完整周一至周日的起止日期，不得使用“某月中旬”等模糊周期。 |

### 5.9 历史导入

| 编号 | 需求 |
| --- | --- |
| IMPORT-001 | 后台支持上传 ChatGPT、Gemini Takeout 或 Chat Memo 导出 ZIP，服务端自动识别格式。 |
| IMPORT-002 | 服务端按文件 SHA-256 去重，重复 ZIP 不重复入队。 |
| IMPORT-003 | 导入任务进入 Worker 队列后异步解析，状态可在导入页和日志页查看。 |
| IMPORT-004 | Worker 每 5 分钟扫描导入 inbox 目录，支持通过 NAS 同步目录投递 ZIP。 |
| IMPORT-005 | 导入失败需要移动到失败目录并记录错误。 |
| IMPORT-006 | processing 导入任务长时间无进度且 PgBoss 中没有对应活跃 job 时，系统应自动恢复为 queued 或标记 failed，避免页面长期误判。 |

### 5.10 本地同步代理

| 编号 | 需求 |
| --- | --- |
| SYNC-001 | 同步代理可以在独立 MacBook 上运行，只要网络能访问归档服务即可。 |
| SYNC-002 | 同步代理配对时只需要服务端地址和配对码。 |
| SYNC-003 | 支持指定 OpenClaw 根目录，默认 `~/.openclaw`。 |
| SYNC-004 | 支持 `--with-codex` 或多个 `--codex-root` 导入本地 Codex 会话。 |
| SYNC-005 | 同步代理读取 JSONL 和 `.gz` 压缩记录，不读取模型密钥或第三方账号凭据。 |
| SYNC-006 | 同步代理保存本地 state，文件大小和 mtime 未变化时不解析、不上传。 |
| SYNC-007 | 网络失败时不得把文件标记为已同步，下次继续重试。 |
| SYNC-008 | 支持 `rebuild` 重新核对全部本地文件。 |
| SYNC-009 | 支持 `--with-claude-code` 和多个 `--claude-code-root`，以 `claude_code` provider 导入 Claude Code 会话。 |
| SYNC-010 | 未压缩 JSONL 仅尾部增长时，从上次 `readOffset` 后读取并上传增量；文件缩短、前部改写、压缩轮换或基线不一致时完整解析。 |
| SYNC-011 | 文件监听扫描执行期间收到新的文件变化时必须合并为一次后续扫描，不能因已有扫描正在运行而丢失 Codex 后续答案。 |
| SYNC-012 | Codex 已同步文件后续增长时，采集时间使用本次实际观察时间，避免 Codex 保持旧 mtime 导致多个修订同刻；首次历史扫描仍保留文件修改时间。 |
| SYNC-013 | Codex JSONL 按 LF 分隔记录，CRLF 行尾只移除末尾 CR；记录内部合法的独立 CR 空白不得被误判为新记录。 |

| SET-008 | 知识抽取应兼容常见 JSON 包装和字段别名；单条会话抽取失败只记录 warning，不得导致整轮报告失败。 |
| SET-009 | 设置页提供规则测试、启停、删除和一键安全规则包；规则测试不得保存文本或发送给模型。 |

| SET-011 | 用户可启动后台清理任务，对已有消息、搜索索引、知识、报告和日志执行不可逆敏感信息脱敏。 |
| SET-012 | 设置页必须使用稳定的二级菜单拆分模型与额度、智能归类、邮件与报告、备份恢复、脱敏安全和系统状态；切换设置项时只展示当前区域。 |

### 5.12 任务状态与日志

| 编号 | 需求 |
| --- | --- |

| OBS-004 | 日志页面以紧凑表格展示分析、采集、分类、设备、导入、系统等操作日志。 |
| OBS-005 | 日志支持按范围、级别、AI 平台、状态和关键字过滤；平台筛选显示各平台 Session 数。 |

| OBS-007 | 所有后台 AI 任务遇到 Token Plan 或速率限制时必须暂停并保留进度；优先使用错误信息或额度接口返回的实际刷新时间，在刷新时间后增加 10 分钟缓冲并自动续跑。无法取得刷新时间时按一小时兜底重试；队列型任务的安全重试周期至少覆盖完整周窗口，不得把受限条目当作普通失败跳过。 |
| OBS-008 | 智能归类、项目知识和报告页面必须明确显示当前 Token Plan 已用完、额度窗口、预计续跑时间和动态倒计时，且不得把额度暂停展示成普通任务失败。 |
| OBS-009 | 设置页必须展示并允许调整 AI 调用节流开关、最小调用间隔和每日 22:00 夜间维护开关。 |
| OBS-010 | Docker 部署必须包含不对宿主机暴露端口的容器监测进程；各项目服务进入专用父 cgroup，监测进程只读访问 `/proc` 与 `/sys/fs/cgroup`，不挂载 Docker Socket。 |
| OBS-011 | 系统状态页必须展示本项目容器汇总的 CPU、内存、Swap 和最近趋势；不得把整台 NAS 的资源使用率展示为项目使用率。项目资源达到 85%/95% 时分别展示 Warning/Critical。 |
| OBS-012 | 系统状态页必须展示应用、容器监测与 PostgreSQL 可用性，以及数据库大小、连接数、活跃连接、最长查询和已记录的 Web 备份时间。 |
| OBS-013 | 项目存储必须按归档数据库和导入文件的实际大小统计。未配置项目存储预算时只展示已用量，不展示容量百分比或磁盘容量告警。 |

## 6. 非功能需求

| 类型 | 需求 |
| --- | --- |
| 隐私 | 会话存储在自托管 PostgreSQL 中；安全凭据入库前打码，手机号、邮箱等其他隐私字段发给模型前脱敏；插件不上传 Cookie。 |
| 安全 | 生产环境要求 HTTPS；管理员启用 TOTP；设备令牌可撤销；敏感设置加密存储。 |
| 可靠性 | 采集、导入、分类、邮件均使用队列或本地 outbox 重试；幂等键避免重复写入；后台支持业务数据导出和重建后导入。 |
| 可观测性 | 关键异步任务都有状态、进度、统计和操作日志。 |
| 性能 | 会话列表分页；分类默认节能模式；长会话按字符上限截断；历史导入后台异步执行。 |
| 可维护性 | 平台适配器独立版本化；共享协议使用 Zod 校验；数据库迁移文件可追踪。 |
| 可移植性 | 支持本地开发、Docker Compose、群晖 Container Manager、Windows 计划任务和 macOS LaunchAgent 同步代理。 |

## 7. 验收标准

1. 在支持平台打开带稳定会话 ID 的网页后，插件无需用户点击即可在后台完成采集或给出部分/失败状态。
2. 腾讯元宝两个 URL 仅第二段不同的会话，归档为两个不同会话。
3. Chrome 插件配对只输入后台生成的配对码，设备名称以后台填写为准。
4. 撤销设备后再次删除，该设备从后台列表移除。
5. `/conversations` 能以紧凑列表显示至少数百条会话，并支持搜索、平台、来源、时间、完整性、采集模式过滤和分页。
6. 点击智能归类后，项目页可以看到分类任务状态、进度和统计。
7. 点击立即生成周报或月报后，报告页可以看到分析任务状态、阶段和错误。
8. OpenAI 兼容模型测试按钮能显示连接成功或失败原因。
9. 导入 ZIP 后，导入页显示排队、解析、完成或失败状态。
10. 日志页能过滤并定位采集失败、分类失败、报告失败、设备配对失败等事件。
11. 打开已完整归档且未变化的会话页面停留时，插件不得重复滚动、重复扫描、重复上传或持续显示“正在采集”。
12. 新回答生成中不采集；生成结束后已有完整基线时优先增量采集，且同一轮回答不在短时间内重复采集。
13. OpenClaw、Codex、Claude Code 文件未变化时不上传；尾部增长时按 offset 读取新增内容；网络失败不推进 offset。
14. 在设置页下载业务备份后，全新部署的网站可导入该备份并恢复会话、项目、知识、报告、设备和设置；管理员账号以新站点为准。
15. 对采集时间相同但创建时间不同的 Codex 修订，默认详情、搜索摘要、导出、仪表盘统计和知识分析均使用后写入的完整修订，答案能够正常显示。
16. 启用安全规则包或运行历史清理后，入库消息、搜索索引、知识、报告和日志中匹配的凭据不可恢复地替换为掩码。

## 8. 已知边界

1. 第三方 AI 网页 DOM 经常变化，适配器需要持续维护。
2. 当前“全量”指当前网页可见分支的全量文本，不等于平台账号内所有历史分支和附件。
3. 模型输出质量会影响分类、知识抽取和报告，系统通过结构化 JSON、字段归一化和本地兜底降低失败率，但不能完全消除模型不稳定。
4. 旧英文包名、备份格式、环境变量和配置目录为兼容性标识；产品显示名称变化不代表这些标识同步改名。
5. 当前实现是单管理员系统，不包含多租户、复杂权限、知识图谱、任务看板、独立向量数据库或手机 App 采集端。
