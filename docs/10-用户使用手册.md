## 1. 产品用途与适用用户

知言归藏把网页 AI 平台以及 OpenClaw、Codex、Claude Code 会话保存到自有服务器；每个会话持续积累一份正文，并通过项目、标签、完整正文搜索、时间线和导出找回内容。系统面向个人或小型自托管归档场景；一个实例只有一个管理员，没有成员邀请、角色或团队空间。

## 2. 初次使用

1. 按部署文档启动 app、worker、host-monitor 和 PostgreSQL。
2. 打开 Web 创建唯一管理员：用户名至少 3 字符，密码至少 11 字符。
3. 立即把 TOTP Secret/URI 加入认证器；初始化不会自动登录。
4. 使用用户名、密码和 6 位动态码登录。
5. 在“设备”页为 Chrome 扩展或本地同步代理生成配对码。
6. 在客户端输入服务器地址和配对码，领取 Token 后开始采集。

配对码 10 分钟有效且只能领取一次。Token 明文只保存在客户端，服务器保存哈希。

## 4. 采集与持续积累

Chrome 当前直接支持 ChatGPT、Gemini、Grok、腾讯元宝、豆包、MiniMax、DeepSeek、千问和 Kimi。升级扩展后，在豆包页面点击扩展内“授权本站并刷新”后可开始采集。

插件自动保存时不会滚动页面或移动输入焦点。ChatGPT 优先直接读取当前会话数据；其他平台或读取失败时，先保存页面已加载的消息。新回答在基线可靠时上传增量；无法确认完整历史时标记为“部分归档”，不会自动滚到顶部补全。

需要补齐历史时，可点浮窗或 Popup 的“完整采集（会滚动）”。插件优先尝试无滚动读取，必要时才滚动加载；你重新打字、点击或滚动页面时会停止手动扫描，并保留你当前的位置。暂停本站或切换会话也会停止当前扫描。

网络失败进入持久 Outbox，自动指数退避；未上传成功时显示“已保存到本地队列，等待上传”。Popup 可查看数量、会话、attempt、错误和下次重试，执行单条/全部重试或确认删除。401 会提示重新配对，但不会删除待上传数据。

本地同步代理只读扫描 OpenClaw、Codex、Claude Code 和 Grok Build CLI/Desktop 文件。同一个会话始终打开一份持续更新的正文，后续采集片段合并进去，片段中没有再次出现的旧消息仍保留。详情显示累计消息数、最近采集时间和归档状态；“部分完成”说明仍有内容或连续性未能确认，可以继续采集补齐。

Codex 一个任务可能发起多个子代理，各自拥有独立 Session。V2.3.3 根据原始子代理父 ID 把它们收纳到主会话下，主列表、项目时间线、首页/项目会话数量和待归类采用同一口径。点击“X 个子代理”可展开并进入完整记录，子代理详情可逐层返回父会话；父子会话各自积累正文，不会互相拼接。相同标题、目录或用户主动 fork 不会触发合并。

若历史会话仍分散显示，请升级保存这些历史的 Windows/macOS 同步代理并执行一次普通补扫。新版会自动读取全部历史 `session_meta` 头部回填关系，不受正文安全窗口限制，无需删除状态、删除归档或 full-rebuild；未归档会话不会因此创建，回收站记录不会恢复。父会话尚未归档或已删除时，子记录仍保留独立访问入口。

## 5. 搜索、常用视图和分页

“会话”关键词搜索标题和完整消息正文。正文命中显示附近摘要，打开后定位到当前累计正文中的消息。`100%` 或 `_value` 会按原字符搜索，不作为数据库通配符。

可组合：平台、来源、complete/partial、full/append/import、起止日期、主项目、最多 20 个标签。多标签为 AND；结束日期为右开边界。

当搜索、项目或标签条件只命中子代理时，列表提升到所属主会话入口；子代理命中提示可带你展开其记录。项目时间线和待归类列表同样提供子代理数量入口。

列表显示准确总数和页码范围；会话、时间线、报告、导入、日志、Activity 和回收站共用分页行为。

要保存筛选，点击“保存当前搜索”并命名；之后从“常用视图”下拉恢复，也可在界面确认删除。

## 6. 批量整理与导出

在会话列表勾选当前页记录，或点击“选择本页”。一次最多处理 500 个会话，可以：

- 设置或清空主项目；设置后为人工锁定；
- 先在批量操作下拉框选择一个标签，再点击“添加标签”或“移除标签”；添加的标签为人工固定。
- 批量下载 CSV、Markdown 或 XLSX；导出只需勾选会话，无需选择标签。生成期间会显示正在处理，完成后提示查看浏览器下载列表。

批量操作忽略已经进入回收站或不存在的 ID，并返回实际处理数量。系统故意不提供批量永久删除。

## 7. 会话累计正文与删除

详情页显示一份累计正文，以及“累计消息”“最近采集”“归档状态”；可查看采集来源、打开原 URL、分配项目、维护标签和导出。页面不再需要选择版本或比较版本。旧版本收藏链接仍可打开统一正文；旧链接中的消息序号不会沿用，以免跳到错误位置。

如果同一条消息在多次采集中出现不同正文，差异内容会保留在底部的“其他采集内容”，默认折叠且不重复计入累计条数。出现“部分片段顺序待核对”时，可展开核对并参考原会话；这些片段不代表已确认连续的问答。

“移入回收站”会让会话离开搜索、项目和报告等常规视图，但数据仍保留。到“回收站”可以恢复；永久删除必须输入大写 `DELETE`。超过 30 天会由 Worker 自动永久清理，因此数据库灾备仍然必要。

导出会过滤部分 system、tool、reasoning 和内部运行时内容，形成面向用户的对话正文。

## 8. 主项目

每条会话最多一个主项目。项目名会做 NFKC、去首尾空格、折叠连续空格和大小写无关去重；纯空格被拒绝，视觉重复提示冲突。

详情中选择项目会人工锁定；点击“交还 AI 调整”释放锁并触发整理。人工调整或释放后旧建议名称会清除。

项目页支持按名称搜索、创建、编辑、归档、恢复和合并。在项目列表上方输入名称关键词，按回车或点击“搜索”，可跨页查找全部项目（含已归档项目）；搜索忽略大小写和全半角差异，点击“清除”恢复完整列表。

点击“合并项目”，可搜索并勾选多个源项目（可含已归档项目），再选择一个保留的目标项目并确认合并后的名称。全部源项目的会话关系和报告引用将一次迁移到目标项目，保留会话的人工锁定状态；任何一步失败都不会留下部分合并结果。合并成功后删除源项目且不可撤销。归档不删除数据但阻止新分配；时间线可以翻遍全部记录，不再只显示前 100 条。

项目页的“可能属于同一项目”位于项目列表与“待归类”之间，会自动检查全部有会话的启用项目，结合名称、说明、每个项目最近的会话标题和共同标签，按组展示值得核对的项目与依据；每组 2–20 个项目，多项目组优先展示。组内各成员必须有相互匹配的依据，不会仅因 A 相似 B、B 相似 C 就把三者归成同一组。列表搜索和分页不会缩小检查范围。只有泛技术词或宽泛标签相同不会单独成为合并依据。“优先核对 / 可核对”表示审阅顺序，不是统计置信度。

配置分析模型后，可点击“AI 补充分析”，补充寻找名称不同但指向同一事项的项目组，每次最多返回 20 组。分析保留所有参与推荐的项目名称，并在请求预算内公平补充经过脱敏的说明、会话标题和标签，不发送会话正文；每个组员都要有可核验的引用。仅名称已超出预算时会明确提示，仍可审阅自动匹配结果。项目材料变化后旧 AI 结果不再展示，可重新分析。候选计算按项目材料指纹复用，翻页或标记不同项目不会重复执行全量匹配。

同组项目可逐项勾选，并可更换保留的目标项目。点击“审阅合并 N 个项目”只会预填所选的多个源项目、目标项目和名称，可以继续修改，最终确认后才执行合并。点击“所选项目保持独立”会记住所选成员之间的全部判断，刷新或重新 AI 分析不会把被否决的组合重新凑入一组；在“已标记不同项目”中可按项目对“恢复检查”。标记及 AI 缓存随系统备份保留，无需数据库升级。

“0 个会话”表示当前没有活跃会话归入该项目，可能来自手动创建、重新归类后留下的旧项目，或早期创建与关联分步执行留下的空壳。空项目不参与合并推荐，界面会列出排除数量；项目记录仍保留，不会自动删除或归档。人工锁定会话不会因为 AI 提议另一个名称而先创建新项目。

## 9. 标签

人工添加标签默认为“人工固定”。可执行：

1. “交还 AI 管理”：关系变为 auto、解除锁定并触发整理，之后 AI 可以调整。
2. “人工固定”：把关系恢复为 manual+locked。
3. “移除”：只删除该会话与标签的关系。

标签页支持词云、创建、搜索、相关会话、重命名、合并和删除。名称按 NFKC、空白和大小写规范化去重。删除标签不会删除会话；合并使用并发锁，避免关系丢失。

## 10. 自动整理

“项目”页可运行增量整理或完整重评。AI 输出一个项目和最多 10 个标签；服务端过滤过细、整句式、低质量、低置信度或重复项。人工项目锁、manual 标签和 locked 标签受保护。

自动整理按实际产品或独立目标判断归属。Codex、OpenAI、SSH 等工具词，以及“周报”“日志”等内容形式，不会单独决定项目。分类材料会剥离内部运行时和插件说明；标题、工作目录与父会话语境仅作辅助，实际正文优先。子会话参考主任务，明确独立的任务仍可单独归组。

已有项目的自动归入或改派需要至少0.82的模型置信度；自动新建项目需要更高置信度。低置信、证据不足或模型不可用时，保留有效旧归属或待归类。人工锁定优先，后台分析期间作出的人工调整也受保护。遇额度/429 时任务保存 offset 和恢复时间自动续跑，不要反复点击。

可配置触发：归档内容更新后、项目变化后、周日 06:15 增量整理、每天 22:00 夜间维护。

## 11. 项目时间线与 Context

项目时间线不调用 AI，按最近采集时间显示完整分页的日期、平台、标题和标签，点击后进入对应会话的累计正文。

生成 Context 时可选择：

- 智能总结 + 历史索引：推荐，会调用已配置的 LLM；
- 仅历史索引：完全不调用 AI。

AI 失败时页面询问是否生成基础版。Context 为即时下载的 `PROJECT-CONTEXT.md`，不持久化。

## 12. 周报、月报与邮件

报告页生成上一完整周或月并分页阅读结果。周期使用实例 `TZ` 且为 `[开始, 结束)`，相邻周期采用互不重叠的时间边界。报告使用符合完整性要求的归档材料；Report 不改变会话、项目和标签。

打开已有报告，点击“重新生成”可重新处理这份报告的原周期，包括历史周报和月报。任务排队或执行期间按钮禁用，页面自动刷新生成状态；成功后显示新正文。新正文通过校验后，与生成完成状态一起保存；失败、材料为空或任务中断时保留原报告，显示原因并允许重试。重新生成不会额外发送邮件，原邮件发送记录保留。

有会话材料的 AI 报告必须包含五个完整章节：周报为“本周主要讨论、关键变化、重要决定、尚未解决、下阶段关注点”，月报为“本月概览、项目演进、关键变化与决定、未解决问题、下月关注点”。系统拒绝缺章、空章节和 `...`、`TODO`、待补充等占位内容；校验失败后自动重试，每轮最多三次正文质量尝试。材料没有记录的事项可明确写“暂无相关记录”。额度受限会保留当前进度，等待记录的恢复时间后再继续；首次生成且无材料时使用无新增会话说明。

详情中的“最近一次生成诊断”可展开查看尝试次数、模型、结束原因、响应长度、输出 token 用量与错误，并进一步展开已脱敏的原始响应；超长响应会截取首尾并标明截断。系统保留当前一轮和上一轮的有限诊断记录，页面显示最近一轮。早期任务没有保存的原始响应无法追溯，不会补造历史诊断。

任务未能进入队列时会显示失败，可重新点击；后台会恢复长时间未接手的排队任务，将长时间无进展的执行任务标记中断。定时任务为实例时区周一 07:30 和每月 1 日 08:00，可在设置关闭。SMTP 测试会真实发信，自动邮件包含完整 Markdown 正文和 Web 详情链接；列表显示邮件状态、时间、attempt和错误，失败项可重试。

报告可下载 Markdown；仍无编辑或删除。

## 13. 历史 ZIP 导入与文件保留

导入页支持 ChatGPT 官方导出、Gemini Takeout 和 Chat Memo ZIP，压缩文件最大 512 MiB；Worker 另检查路径、条目数、单项和总展开大小。

ZIP 不是总事务。第 801 条失败时前 800 条仍保留，界面以 partial 显示 imported、unchanged、failed、total，而不是把“失败”解释为零导入。

failed/partial 可直接点击重试；重新上传同一 SHA-256 ZIP 也会复用原 ImportJob 重新执行。若失败目录中的 ZIP 已被清理，手动重试返回提示，需要重新上传。

Processed/Failed ZIP 按环境变量保留，默认各 30 天。可清理过期文件或立即清理全部；只删除 ZIP，不删除导入结果。系统状态显示 Inbox/Processed/Failed 文件数与空间。

## 14. 归档可靠性、活动和排障入口

优先查看总览“需要处理”：不完整会话、近 24 小时采集失败、超过 24 小时未恢复、设备离线和导入失败/部分完成均可点入业务页。设备页的 Adapter Health 可识别某平台/版本连续失败或 partial率异常；本地代理状态显示版本、OS、扫描、同步和错误。

“活动”汇总后台任务与异常，“日志”提供1h/24h/7d/30d、自定义日期和scope/level/provider/device/status/q筛选。两者均分页。“设置 → 系统状态”可运行只读归档完整性检查或重建全文索引。若Chrome虚拟列表仍出现partial，先打开完整历史、滚到顶部/底部稳定后手动重采。

## 15. 账号与 Session 安全

“设置 → 账号与安全”支持：

- 用当前密码和 TOTP 修改密码；新密码至少 11 字符；
- 重新绑定 TOTP：先生成限时待确认密钥，再用新验证器验证码确认；确认前旧验证码仍有效，可取消切换；
- 查看当前和其他浏览器 Session；
- 注销一个其他 Session，或一次注销全部其他 Session。

如果当前 Session 被注销，本浏览器需要重新登录。系统没有忘记密码邮件流程；丢失密码/TOTP时，由拥有服务器Shell、数据库连接和`APP_MASTER_KEY`的运维者运行管理员恢复CLI，可重置密码、TOTP或注销全部Session。

## 16. 备份、恢复与脱敏

Web 业务备份在同一个 PostgreSQL repeatable-read 快照中导出 18 张业务表，包含常用视图，不含管理员、Session、配对码、RestoreJob、派生全文分块和 PgBoss。可先使用“验证备份”检查文件而不写数据库。

正式恢复上传完成后返回任务而不是等待整个过程；页面显示校验、替换、搜索重建和一致性验证进度。开始替换前可取消，之后系统进入维护模式且不可取消。提交前失败可在保留期内完整重试或删除恢复文件；如果显示“需要恢复处理”，说明事实数据已经提交，系统会保持维护模式，点击“继续恢复后处理”只重建搜索并检查完整性。completed 后才表示全部完成。Restore Worker 仍受压缩512MiB、解压1GiB和进程内存限制。

不同 `APP_MASTER_KEY` 时加密设置不恢复，需要重填 API Key/SMTP 密码。Web 业务备份不代替 PostgreSQL 灾备：重大升级前仍应做数据库级备份并验证恢复。

历史归档脱敏不可逆。先用虚构文本测试规则，执行前备份。

## 17. 常见问题

**搜索不到极长会话末端**：确认已执行 migration 0018；必要时在“设置 → 系统状态”重建全文检索。标题/摘要只是辅助，完整正文分块才是 V2.3 主检索来源。中文连续文本保留字面 ILIKE 回退。

**自动整理一直等待**：检查 Worker、任务恢复时间和额度，不要重复创建同类任务。

**交还 AI 后标签暂未变化**：关系已经切换为 auto，但最终是否删除/替换取决于下一次模型结果和规则；可查看活动与日志。

**Context 智能版失败**：选择页面提示的基础版，或直接选择“仅历史索引”。

**导入重试提示文件不存在**：原 failed ZIP 已过保留期或被立即清理；重新上传原 ZIP 即可。

**Chrome 找不到豆包采集**：升级扩展，在豆包会话页点击“授权本站并刷新”，并确认 URL 带会话ID；首页不会生成共享会话ID。

**恢复旧备份有 warning**：旧 knowledge 数据会忽略，旧项目名会规范化；核对 Conversation/Revision/Message、项目、标签、报告和常用视图计数。

## 批量补采 ChatGPT 不完整归档（V2.4.8）

1. 从“设备”页下载本次发布的最新 Chrome 扩展并完成配对，确认执行补采的同一个 Chrome 已登录 ChatGPT。新扩展运行后会用真实 manifest 版本更新设备心跳；补采页的“执行设备上报版本”显示该设备最近上报值，未上报时不会猜测装机版本。
2. 从侧栏进入独立“批量补采”页面，选择执行设备并点击“补采全部 ChatGPT 不完整会话”。也可在“会话”页勾选后点击“补采已选会话”，进入补采页面再创建任务。“全部”不受列表筛选条件限制，每次最多 500 条。设备默认按最近连接时间选择，请核对名称与当前扩展一致。
3. 保持 Chrome 打开。扩展一次打开一个专用标签页；无需停留在归档网页。暂停会在当前一条完成后停止，继续可恢复剩余队列。
4. 单条会话无权访问、已删除、跳回首页或 90 秒内未加载内容时自动跳过，并在逐条结果中保留原因；其他单条采集失败也继续下一条。登录失效、验证码、限流或扩展无法连接时队列暂停。检查 ChatGPT 后点击“继续”；关闭或手动跳转专用标签页也会触发暂停。旧版扩展已卡住的条目可点击“跳过当前条并继续”。
5. 进行中和暂停任务默认展开；完成、取消的任务收进默认折叠的“历史任务”，展开后可查看逐条结果，分别重试仍不完整、失败和已跳过条目。取消队列保留已经入库的内容，不删除原归档；其他网站及本地 Codex/OpenClaw 归档暂不支持此入口。

页面的“任务进度刷新失败”“执行设备加载失败”和任务操作失败分别表示不同请求出错。500/502 等会显示具体 HTTP 状态，429 表示请求限流；进度读取会稍后重试，成功后清除对应提示，已有进度继续保留。登录或权限问题需处理后点击“刷新”。

若提示“操作已提交，进度刷新失败”，先刷新查看任务状态，不要重复提交。页面不会自动重复创建任务、继续或重试条目，也不会因为一次读取恢复而自行恢复已暂停的队列。逐条结果中的无权访问、已删除或加载失败属于原会话采集问题，应先在同一 Chrome 核对该条原链接、登录账号与工作区，再决定是否重试已跳过项。

“待上传”中的“全部重试”仍用于上传已保存快照，不等同于批量重新读取原会话。
