## 1. 产品用途与适用用户

知言归藏把网页 AI 平台以及 OpenClaw、Codex、Claude Code 会话保存到自有服务器，保留每次 Revision，并通过项目、标签、完整正文搜索、时间线、Diff 和导出找回历史。系统面向个人或小型自托管归档场景；一个实例只有一个管理员，没有成员邀请、角色或团队空间。

## 2. 初次使用

1. 按部署文档启动 app、worker、host-monitor 和 PostgreSQL。
2. 打开 Web 创建唯一管理员：用户名至少 3 字符，密码至少 12 字符。
3. 立即把 TOTP Secret/URI 加入认证器；初始化不会自动登录。
4. 使用用户名、密码和 6 位动态码登录。
5. 在“设备”页为 Chrome 扩展或本地同步代理生成配对码。
6. 在客户端输入服务器地址和配对码，领取 Token 后开始采集。

配对码 10 分钟有效且只能领取一次。Token 明文只保存在客户端，服务器保存哈希。

## 4. 采集与 Revision

Chrome 当前直接支持 ChatGPT、Gemini、Grok、腾讯元宝、MiniMax、DeepSeek、千问和 Kimi。豆包可出现在历史数据筛选中，但当前扩展不能直接采集。

插件先做轻量变化判断；首次采集、分支变化、增量基线不匹配或虚拟列表中找不到基线消息时，执行完整扫描。新回答通常上传增量。网络失败进入持久 Outbox，自动指数退避；Popup 可查看数量、会话、attempt、错误和下次重试，执行单条/全部重试或确认删除。401 会提示重新配对，但不会删除待上传数据。

本地同步代理只读扫描 OpenClaw、Codex 和 Claude Code 文件。详情页“版本”下拉可查看历史：complete 表示顶部、底部和稳定状态均确认；partial 表示可能未加载完整。旧 Revision 不会被新捕获覆盖。

## 5. 搜索、常用视图和分页

“会话”关键词搜索标题和完整消息正文。正文命中显示附近摘要，打开后定位到指定 Revision 和消息。`100%` 或 `_value` 会按原字符搜索，不作为数据库通配符。

可组合：平台、来源、complete/partial、full/append/import、起止日期、主项目、最多 20 个标签。多标签为 AND；结束日期为右开边界。

列表显示准确总数和页码范围；会话、时间线、报告、导入、日志、Activity 和回收站共用分页行为。

要保存筛选，点击“保存当前搜索”并命名；之后从“常用视图”下拉恢复，也可在界面确认删除。

## 6. 批量整理与导出

在会话列表勾选当前页记录，或点击“选择本页”。一次最多处理 500 个会话，可以：

- 设置或清空主项目；设置后为人工锁定；
- 添加人工固定标签；
- 移除指定标签；
- 批量下载 CSV、Markdown 或 XLSX。

批量操作忽略已经进入回收站或不存在的 ID，并返回实际处理数量。系统故意不提供批量永久删除。

## 7. 会话详情、Revision Diff 与删除

详情页可切换 Revision、查看来源信息、打开原 URL、分配项目、维护标签和导出。点击“与上一版本比较”查看新增、修改、移除消息，以及 V2.3 新采集的历史标题/URL变化。Migration 前 Revision 会显示历史元数据不可验证，不用当前标题伪造过去状态。

“移入回收站”会让会话离开搜索、项目和报告等常规视图，但数据仍保留。到“回收站”可以恢复；永久删除必须输入大写 `DELETE`。超过 30 天会由 Worker 自动永久清理，因此数据库灾备仍然必要。

导出会过滤部分 system、tool、reasoning 和内部运行时内容，形成面向用户的对话正文。

## 8. 主项目

每条会话最多一个主项目。项目名会做 NFKC、去首尾空格、折叠连续空格和大小写无关去重；纯空格被拒绝，视觉重复提示冲突。

详情中选择项目会人工锁定；点击“交还 AI 调整”释放锁并触发整理。人工调整或释放后旧建议名称会清除。

项目页支持创建、编辑、归档、恢复和合并：归档不删除数据但阻止新分配；合并会移动关系和报告引用、删除源项目且不可撤销。时间线可以翻遍全部记录，不再只显示前 100 条。

## 9. 标签

人工添加标签默认为“人工固定”。可执行：

1. “交还 AI 管理”：关系变为 auto、解除锁定并触发整理，之后 AI 可以调整。
2. “人工固定”：把关系恢复为 manual+locked。
3. “移除”：只删除该会话与标签的关系。

标签页支持词云、创建、搜索、相关会话、重命名、合并和删除。名称按 NFKC、空白和大小写规范化去重。删除标签不会删除会话；合并使用并发锁，避免关系丢失。

## 10. 自动整理

“项目”页可运行增量整理或完整重评。AI 输出一个项目和最多 10 个标签；服务端过滤过细、整句式、低质量、低置信度或重复项。人工项目锁、manual 标签和 locked 标签受保护。

模型不可用时会话可能使用本地粗分类或保持待归类。遇额度/429 时任务保存 offset 和恢复时间自动续跑，不要反复点击。

可配置触发：新 Revision 后、项目变化后、周日 06:15 增量整理、每天 22:00 夜间维护。

## 11. 项目时间线与 Context

项目时间线不调用 AI，显示完整分页的日期、平台、标题、标签及对应 Revision 链接。

生成 Context 时可选择：

- 智能总结 + 历史索引：推荐，会调用已配置的 LLM；
- 仅历史索引：完全不调用 AI。

AI 失败时页面询问是否生成基础版。Context 为即时下载的 `PROJECT-CONTEXT.md`，不持久化。

## 12. 周报、月报与邮件

报告页生成上一完整周或月并分页阅读结果。周期使用实例 `TZ` 且为 `[开始, 结束)`，相邻周期不会重复边界 Revision。只使用完整 Revision；Report 不改变会话、项目和标签。

任务未能进入队列时会立即显示失败，可重新点击；不会永久停留 queued。定时任务为实例时区周一 07:30 和每月 1 日 08:00，可在设置关闭。SMTP 测试会真实发信，自动邮件只含摘要和 Web 详情链接；列表显示邮件状态、时间、attempt和错误，失败项可重试。

报告可下载 Markdown；仍无编辑或删除。

## 13. 历史 ZIP 导入与文件保留

导入页支持 ChatGPT 官方导出、Gemini Takeout 和 Chat Memo ZIP，压缩文件最大 512 MiB；Worker 另检查路径、条目数、单项和总展开大小。

ZIP 不是总事务。第 801 条失败时前 800 条仍保留，界面以 partial 显示 imported、unchanged、failed、total，而不是把“失败”解释为零导入。

failed/partial 可直接点击重试；重新上传同一 SHA-256 ZIP 也会复用原 ImportJob 重新执行。若失败目录中的 ZIP 已被清理，手动重试返回提示，需要重新上传。

Processed/Failed ZIP 按环境变量保留，默认各 30 天。可清理过期文件或立即清理全部；只删除 ZIP，不删除导入结果。系统状态显示 Inbox/Processed/Failed 文件数与空间。

## 14. 归档可靠性、活动和排障入口

优先查看总览“需要处理”：不完整会话、近 24 小时采集失败、超过 24 小时未恢复、设备离线和导入失败/部分完成均可点入业务页。设备页的 Adapter Health 可识别某平台/版本连续失败或 partial率异常；本地代理状态显示版本、OS、扫描、同步和错误。

“活动”汇总后台任务与异常，“日志”提供1h/24h/7d/30d、自定义日期和scope/level/provider/device/status/q筛选。两者均分页。“设置 → 系统状态”可运行只读归档完整性检查或重建全文索引。若Chrome虚拟列表仍出现partial，先打开完整历史、滚到顶部/底部稳定后手动重采。

## 15. 账号与 Session 安全

“设置 → 账号与安全”支持：

- 用当前密码和 TOTP 修改密码；新密码至少 12 字符；
- 重新绑定 TOTP：先生成限时待确认密钥，再用新验证器验证码确认；确认前旧验证码仍有效，可取消切换；
- 查看当前和其他浏览器 Session；
- 注销一个其他 Session，或一次注销全部其他 Session。

如果当前 Session 被注销，本浏览器需要重新登录。系统没有忘记密码邮件流程；丢失密码/TOTP时，由拥有服务器Shell、数据库连接和`APP_MASTER_KEY`的运维者运行管理员恢复CLI，可重置密码、TOTP或注销全部Session。

## 16. 备份、恢复与脱敏

Web 业务备份在同一个 PostgreSQL repeatable-read 快照中导出 18 张业务表，包含常用视图，不含管理员、Session、配对码、RestoreJob、派生全文分块和 PgBoss。可先使用“验证备份”检查文件而不写数据库。

正式恢复上传完成后返回任务而不是等待整个过程；页面显示校验、替换、搜索重建和一致性验证进度。开始替换前可取消，之后系统进入维护模式且不可取消。提交前失败可在保留期内完整重试或删除恢复文件；如果显示“需要恢复处理”，说明事实数据已经提交，系统会保持维护模式，点击“继续恢复后处理”只重建搜索并检查完整性。completed 后才表示全部完成。Restore Worker 仍受压缩512MiB、解压1GiB和进程内存限制。

不同 `APP_MASTER_KEY` 时加密设置不恢复，需要重填 API Key/SMTP 密码。Web 业务备份不代替 PostgreSQL 灾备：重大升级前仍应做数据库级备份并验证恢复。

历史归档脱敏不可逆。先用虚构文本测试规则，执行前备份。

## 17. 常见问题

**搜索不到极长会话末端**：确认已执行 migration 0018；必要时在“设置 → 系统状态”重建全文检索。标题/摘要只是辅助，完整正文分块才是 V2.3 主检索来源。中文连续文本保留字面 ILIKE 回退。

**自动整理一直等待**：检查 Worker、任务恢复时间和额度，不要重复创建同类任务。

**交还 AI 后标签暂未变化**：关系已经切换为 auto，但最终是否删除/替换取决于下一次模型结果和规则；可查看活动与日志。

**Context 智能版失败**：选择页面提示的基础版，或直接选择“仅历史索引”。

**导入重试提示文件不存在**：原 failed ZIP 已过保留期或被立即清理；重新上传原 ZIP 即可。

**Chrome 找不到豆包采集**：当前扩展未实现豆包 adapter，可通过已支持的历史导入来源保存已有数据。

**恢复旧备份有 warning**：旧 knowledge 数据会忽略，旧项目名会规范化；核对 Conversation/Revision/Message、项目、标签、报告和常用视图计数。
