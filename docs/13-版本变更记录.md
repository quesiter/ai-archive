# 知言归藏版本变更记录

本文件合并原 `docs/UPDATE-*.md` 的版本说明。具体部署、升级、备份和排错步骤统一查看 [09-运行维护](09-运行维护.md)。

> 阅读说明（2026-08-28）：以下条目记录各版本发布时的真实声明，不等于当前功能清单。后续版本删除或调整的旧能力（例如“项目知识”）仍保留在历史条目中；当前导航、能力边界和已知问题以 [01-产品功能与业务规则](01-产品功能与业务规则.md) 为准。

## 2026-11-01 V2.4.12：性能优化、采集适配与归档核验

- 中文单字、双字改为 B-tree 词条等值查找；长短语先求全部相邻双字交集，再在候选修订内核对实际分块，首个命中即停。长短语与摘要复用现有 trigram 和修订索引，不新增正文 GIN。
- 移除搜索文档全文副本。追加采集只从新增消息分块提取、提交新增词条，元数据更新跳过搜索写入；改写、重排和修订合并执行完整校准，缺失索引按256块分页恢复。
- 搜索计数与分页共用一次命中集；标签、完整性、来源设备等筛选在 SQL 内执行，保留标题、历史修订及父会话命中。
- 会话列表核对计数和文本统计改读持久化汇总；项目时间线按当前修订在 SQL 排序分页，详情和历史证据支持消息分页及搜索定位。
- 首页改读项目归属汇总，随归属、父子关系和活动变更更新，只返回最近12个有增长项目及完整总数；修复原生 SQL 的 Date 参数编码。
- 停写重复 search_text，保留业务备份兼容；Web 按路由拆包并明确接口类型。
- 增加豆包实页采集适配，保留消息标识和思考内容；支持本地 Grok CLI、Grok Build Desktop 日志采集及 Windows/macOS 启动器。
- Migration 0027–0030 建立并维护归档汇总、词条与引用结构，移除搜索全文副本；原始消息不裁剪，恢复与脱敏后从真实分块重建派生索引。
- 全工作区发布校验及真实 PostgreSQL 的 API、项目、搜索生命周期流程通过，覆盖追加写入、备份恢复、脱敏、永久删除和事务回滚；生产保留 EXPLAIN、完整命中集合摘要及备份。

## 2026-10-26 V2.4.8：批量补采可靠性修复

### 批量补采可靠性修复

- 批量补采页面将任务进度刷新、执行设备加载和任务操作错误分别展示，包含有用的 HTTP 状态和原因；短暂读取失败恢复后只清除对应提示，保留上次成功读取的任务进度。
- 自动轮询同一时刻只发出一个进度请求；任务操作前取消旧读取并丢弃迟到结果，避免旧失败覆盖新状态。读取失败按退避重试，限流遵循 `Retry-After`；登录或权限问题等待处理后手动刷新。
- 操作成功但后续刷新失败时明确显示“操作已提交”，不自动重放新建、继续或重试等 POST；请求超时会释放页面操作状态，并提示先核对任务结果。
- API 客户端补充空错误消息、HTTP/2 空状态文本、非 JSON 失败响应和网络异常的可读说明，避免只显示通用 `Error`；取消请求仍由调用者识别。
- Chrome 扩展按实际 manifest 版本发送设备心跳，补采页展示设备上报版本，不再把静态旧版本或适配器版本当作当前装机版本；下载组件以设备页最新发布包为准。
- 服务端、Web、Chrome、Windows/macOS 本地同步代理和共享协议源码统一为 V2.4.8；安装包需重新构建校验后发布，不会自动替换已安装扩展或自行继续已暂停的补采任务。本条记录功能变更；完整发布验证和生产部署结果另行记录。

### 项目分类证据策略修正

- 分类只按真实产品或独立目标判断，剥离运行时、插件及 AGENTS 指令块；标题、工作目录、技术词和被引用的项目名只作辅助线索。
- 移除技术词粗桶兜底与相关性额外加分，已有长期项目不再因为名称较长而被过滤；模型失败和证据不足时保留有效旧归属或待归类。
- 自动归入或改派已有项目的最低置信度为0.82；有启用项目时新建阈值0.88、空库0.85。泛主题不再自动新建；复用既有泛主题需要用户实际正文的明确工作范围证据。
- 子会话增加有限、脱敏的父/根任务语境，不强制整树归到同一项目；独立任务需有明确证据。人工锁和分析期间的新归属保持数据库原子保护，归档项目不能被同名建议隐式复用。

## 2026-10-25 V2.4.7：性能与稳定性完善

- 修复本地代理监听路径与 Chokidar 4 的兼容性，使用实际目录监听及来源过滤，覆盖仅监听模式、新建目录、文件追加和授权撤销。
- Claude Code 损坏中间日志行保留可读内容并明确标记不完整；损坏增量回退全量校验，旧适配器状态自动重新解析。
- 队列初始化失败后允许重试，清理部分启动资源，协调并发初始化和关闭；数据库短暂不可用不再永久缓存失败结果。
- 备份恢复按可用内存和 V8 堆余量限制解压与解析，内存不足时给出可操作错误；恢复复用一次解析结果，按批次转换入库，保留原有事务与提交检查点。
- 网页按需加载 Markdown 解析器和历史版本说明，展示数据使用独立入口，首页不初始化协议校验器，降低登录及首页首次加载体积。
- 产品组件统一为 V2.4.7；Chrome manifest 从组件元数据读取版本，客户端打包拒绝错误版本，NAS 包按组件真实版本选包并核验当前构建内容。
- 搜索摘要由逐结果查询改为一次批量读取，避免每页 50 条结果产生约 55 次查询；新增 `0026_search_content_trigram`，为正文包含搜索建立 GIN trigram 索引，保留原全文检索索引。首次升级会创建索引，大库需预留磁盘与维护时间。
- 发布资格新增组件版本一致性、依赖审计、启动器和打包回归检查，区分自动化通过和真实环境验收。当前迁移为 0000–0026；验证范围见测试与质量保证文档，安装包不会自动部署或替换已安装组件。

## 2026-10-12：登录持久化

- Web 登录有效期延长到 90 天，活跃会话每日自动续期；现有未过期会话首次使用时自动延长。Cookie 使用 HttpOnly、SameSite=Lax、Expires 和 Max-Age，生产环境继续使用 Secure，同源写操作检查保持有效。
- 相关 50 项测试及服务端类型检查通过；已部署到 `codex-day`，线上验证数据库与 Cookie 同步续期、每日续期节流及撤销后返回 401，健康接口正常。

## 2026-10-08 V2.4.4：批量补采与完整性判定完善

- 修复会话页批量导出按钮颜色过浅、看似禁用的问题；标签操作明确提示先选择标签，项目、标签和导出控件分组排布。批量导出增加生成中、下载已发起和失败提示，生成期间防止重复点击。

- 新增独立“批量补采”页面 `/recapture`，侧栏和会话页均可进入；会话列表保留“补采已选会话”入口，可将已选或全部 ChatGPT 不完整会话加入队列，指定已配对的 Chrome 扩展逐条重新读取原会话，更新原归档。一次最多 500 条，其他网站和本地同步会话暂不进入浏览器批量补采。
- 进行中和暂停任务默认展开，已完成、已取消任务自动收进默认折叠的“历史任务”，展开后仍可查看结果与重试。执行设备默认选择最近连接的有效 Chrome 扩展并显示连接时间，任务进度增加正在采集条数，减少设备选择和进度理解上的歧义。
- 队列持久保存在服务端，展示待处理、正在采集、已完整、仍不完整、失败、已跳过的逐条进度；支持暂停、继续、取消，以及失败、仍不完整、已跳过条目的重试；暂停后可跳过当前无法处理的条目并继续。暂停会完成当前一条，取消保留已写入的归档。
- Chrome 扩展使用专用标签页顺序采集，支持后台重启恢复和任务租约；不会复用用户原有标签页。单条会话无权访问、已删除、跳回首页或 90 秒内未加载内容时自动跳过并记录原因；其他单条采集失败也继续下一条。登录失效、验证码、限流、扩展无法连接或用户关闭/切换专用页面时暂停队列，处理后可继续。归档被删除后不通过过期任务恢复它。
- 补采成功以对应设备、会话和任务的新入库回执为准；仍有内容缺失或待核对差异时继续显示不完整。完整性遵循“页面当前分支可见内容已全部归档”，不要求 AI 回答结束或凑齐问答轮次，源回答状态单独说明。
- 服务端、网页、Chrome 扩展、本地同步代理和共享协议源码统一为 V2.4.4；ChatGPT 适配器升级为 1.2.17。新增 `0025_recapture_jobs` 数据库迁移，补采队列纳入备份，恢复备份后暂停待执行队列，需手动继续。

## 2026-10-07 V2.4.3：全天更新汇总、项目归类与界面完善

### 全天更新汇总、项目归类与界面完善

### 采集、同步与归档修复

- 2026-10-08 同版本补丁（ChatGPT 适配器 1.2.15，服务端兼容 1.2.14）：完整性只表示页面当前分支内容已全部采集，不要求源回答结束或完整问答轮次。原生分支完整读取时归档显示完整，源回答状态单独保留说明；无法解析的正文仍显示不完整。手动采集不再等待 AI 结束回答；同一消息正文变化时保留已确认的原生顺序，只提示正文差异。

- 2026-10-08 同版本服务端补丁：完整原生分支核对可保留并隔离早期无稳定 ID 的采集片段，避免旧片段阻止当前正文顺序和时间恢复。仅按已知正文哈希识别历史片段，新出现的未知内容继续提示核对；会话列表与详情区分“原文待核对”和历史未采全，历史正文、差异及搜索定位均保留。

- V2.4.3 补丁补充（ChatGPT 适配器 1.2.14）：`unfinished_message` 只影响对应正文的完整性，不再导致整条原生历史被拒绝。保存已读取的父链、原始发送时间和消息位置，保留未完成说明；服务端将顺序确认与正文完整性分别记录和显示，不把未知正文标为完整。

- V2.4.3 同版本补丁（ChatGPT 适配器 1.2.13）：原生历史读取支持图片引用、文件附件和已中止回答，未知内容保留正文与位置并明确标记部分完成，避免一条附件导致整段历史被拒绝。原始发送时间可补入早期 DOM 归档；无法确定发送时间时显示“发送时间未知”，不再把入库日期当作发送日期。
- 仅经过完整父链、当前分支和稳定消息 ID 校验的新原生快照，可以确认当前正文顺序；历史编辑和渲染差异继续保留在其他采集内容中。局部 DOM 快照不会隐藏历史消息或冒充首轮，后续自动采集不会破坏已确认的顺序。完整采集展示阶段与等待进度，截图、复制快捷键和页面自身输入事件不会误中止采集。

- 汇总当天服务端、Web、Chrome、Windows/macOS 同步代理和共享协议的源码更新，源码产品版本统一为 V2.4.3；ChatGPT 适配器版本仍为 1.2.11，与产品版本分别管理。此前 V2.4.2 发布包与部署记录保留，不把旧包重命名为新版本；V2.4.3 安装包需重新构建与校验后发布。
- Windows/macOS 同步补齐全部历史 Codex session_meta 父子关系；仅含工具内容、没有有效用户正文的辅助记录记为跳过，并保留原因。Windows 重新配对保留采集目录和进度，修复脚本随包分发；macOS 打包校验启动脚本换行和执行权限。
- Chrome 改进长会话扫描、原生正文读取和待上传重试；采集条数与完整性遵循服务端回执，分别展示本次保存和累计归档。页面采集脚本未连接时提示刷新或检查访问权限，自动采集保持静默。
- 完善来源设备与完整性组合筛选、重新配对后的逻辑设备身份和来源追溯；已撤销、已解除配对的设备默认折叠，可展开查看。
- 增加完整本机 Codex JSONL 的受控修复工具，校验原文件 SHA-256 与归档基线，支持试运行、修复前备份和按会话事务重建正文、哈希、搜索索引；历史证据和修复来源继续保留。本次 QML-PC 的 74 条不完整会话已恢复，其中 8 条片段合并、66 条原始历史重建；结果限于本次核验范围。
