## 2026-08-28 V2.3.0：长期归档可靠性与运维可诊断性

### 正确性与账号恢复

- Settings 服务端按键执行严格 Schema 校验：运行模式只允许 `economy/full`，正文上限为 2,000–40,000，其余布尔、端口和节流字段也拒绝脏值。
- `TZ` 成为实例日历的唯一口径，统一 Cron、周/月报窗口、夜间任务键、API 日期边界与 Web 日期筛选；支持 IANA 时区与 DST。
- TOTP 重绑改为 pending → 新验证码确认 → activate 两阶段流程，确认前旧验证器持续有效；新增服务器侧管理员改密、重置 TOTP、注销 Session CLI。
- Windows 源码入口与便携入口收敛为同一 PowerShell 核心，发布包包含同一 wrapper，完整重建仍需显式命令。

### 采集与长期诊断

- CaptureRun 保存 `adapterVersion/messageCount`；设备回传客户端版本、OS、扫描/成功同步/错误时间、错误码、跟踪和跳过文件数。
- 设备页增加按 provider + adapterVersion 的 24 小时/7 天成功率、部分率、失败率、平均消息量与连续失败健康判断。
- Chrome Popup 增加持久 Outbox 管理：数量、平台、会话、加入时间、尝试次数、HTTP 状态、下次重试、单条/全部重试和删除。
- Chrome 和本地 Agent 遇 401 进入 `AUTH_REVOKED`，停止普通重试并保留待上传数据；重新配对后继续。Agent 对网络、429、5xx 指数退避，对 409 回退完整采集，对其他 4xx 不无限重试。

### 恢复、校验与完整性

- Web Restore 改为流式上传暂存 + Restore Job + Worker；阶段为 validating、validated、restoring、rebuilding_search、verifying、completed，替换数据开始后进入维护模式并禁止取消。
- Restore 事务提交时原子记录 `factsCommittedAt`；提交后重建/验证失败进入 `recovery_required` 并持续维护模式，重试只执行恢复后处理。
- Restore staging 增加默认30天failed保留期、每日housekeeping、手动删除和System Status空间统计；新装/升级同时为imports与restores授予UID 1000必要权限。
- 设置页可只验证备份，不写数据库；校验 gzip、格式、Schema、18 张表、引用、delta 基线、计数和主密钥指纹。
- 新增手动及每日 Archive Integrity Check，验证 Revision 链/循环/跨会话基线、重建、独立内容完整性哈希、消息序号、孤儿关系和缺失搜索分块；旧/合法脱敏记录明确计为不可验证而非损坏。
- Revision 新增采集时标题和 canonical URL，Diff 可显示元数据变化；V2.3 之前记录明确标记为不可验证，不用当前标题伪造历史。
- 内容 snapshotHash、含标题/URL的 Revision identity 与可重建内容完整性 hash 分离，既保留升级前幂等兼容，也能记录纯元数据变化并避免脱敏后的完整性误报。
- Report 增加 Markdown 下载、邮件投递状态、错误、尝试次数和失败重试。

### 性能、UI 与工程质量

- Project Overview 拆成统计、分页项目、分页未归类和轻量 options；不再一次返回全部关系。
- 历史脱敏扩展到 Project 名称/描述、Tag 名称和 Saved Search 名称/query；Settings 继续只按白名单处理。
- 日志增加 1h/24h/7d/30d 与自定义日期范围；Saved Search 增加删除 UI；系统状态增加搜索重建和完整性检查入口。
- 新增中文搜索 `P50/P95/P99 + EXPLAIN ANALYZE` 基准工具和 Release Qualification 脚本；默认仍使用 PostgreSQL，不引入 Elasticsearch、向量库或 RAG。
- 服务端、Web、Chrome、本地同步代理与共享包统一为 `V2.3.0`；新增 migration 0019–0021。

### 工程文档与发布收口

- 文档统一为 00–13 编号中文文件名，按产品规则、SRS、架构与详细设计、界面、数据库、接口、测试、部署、运维、用户、客户端和变更记录组织。
- 原“架构概览”合并进系统架构与详细设计，原发布冻结清单扩展为测试与质量保证计划；新增文档配置控制、需求 ID、追踪矩阵、缺陷等级和发布准出标准。
- 仓库 `release/` 清除 V2.3.0 以前的重复二进制交付物，只保留当前发布包、校验清单和资格证据；历史文件继续由 Git 历史追溯。
- NAS clean-install 打包器固定内嵌当前 Chrome、Windows、macOS 客户端，拒绝旧版本、NAS 包自身和敏感/运行数据；Docker 镜像构建已纳入发布前验证。
- NAS 更新脚本调整为先启动 app、等待长耗时 migration 与目标版本 HTTP 健康检查完成，再以 `--no-deps` 启动 worker；默认健康等待窗口扩展到 120 分钟，避免百万级全文分块首次回填和短暂滞后的 Docker 健康状态被误判为发布失败。

- Node.js 22 Release Qualification 的类型检查、242 项测试和生产构建全部通过；Compose、Markdown 链接、发布包结构与 SHA-256 校验通过。

## 2026-08-27 V2.2.0：正确性、可靠性与长期归档质量

### 数据正确性

- Chrome 虚拟列表找不到增量基线末消息时改做完整扫描，不再保守跳过。
- 周报/月报材料窗口统一为 `[windowStart, windowEnd)`；报告入队返回空 jobId 时立即把运行标记 failed，可重新发起。
- 项目名统一执行 NFKC、trim、连续空格折叠与规范名唯一约束；空名返回 400，规范冲突返回 409。
- 会话、标签和日志的 `%`、`_`、反斜杠按字面搜索。
- 标签“解锁”改名为“交还 AI 管理”，同时把关系切换为 auto；Tag 合并改为事务内稳定顺序 advisory lock。
- 人工分配、释放和项目合并会清空过期 `suggestedName`。

### 长期可靠性

- Web 业务备份使用 PostgreSQL REPEATABLE READ 只读快照覆盖计数和逐表流式导出；恢复完成后返回 200，并重建全文检索分块。
- 历史导入新增 `attempt`、`lastRetryAt`、failed/partial 重试、同哈希失败 ZIP 重新上传、部分完成计数和入队失败闭环。
- Processed/Failed ZIP 默认保留 30 天，可配置、手动清理；系统状态分别显示 Inbox、Processed、Failed 空间。
- Worker 每天 03:20 清理过期 Session、未领取配对码、导入 ZIP 和超过 30 天的回收站会话。
- 会话、时间线、报告、分析运行、导入、日志和 Activity 使用统一 `{items,pagination}` 返回结构和 Web 分页控件。
- Project Context 提供“智能上下文”和“不使用 AI 的历史索引”，智能失败可回退。

### 产品质量

- 会话详情增加与上一 Revision 的消息 Diff，分别显示新增、修改和移除；标题尚未版本化时明确说明。
- 总览增加“需要处理”可靠性中心，聚合不完整会话、采集失败、超时未恢复、离线设备和失败导入。
- 会话删除进入 30 天回收站，可恢复或输入 `DELETE` 永久删除。
- 设置增加账号安全：修改密码、重绑 TOTP、查看 Session、注销指定或其他会话。
- 会话列表增加多选、批量设置项目、添加/移除标签和 CSV/Markdown/XLSX 导出；不提供批量永久删除。
- 增加保存搜索、Activity 页面以及 `conversation_search_chunks` 完整历史检索架构；分块由原始消息重建，不引入向量数据库或 RAG。

### 版本与迁移

- server、Web、Chrome 升级为 `V2.2.0`；同步代理与共享协议保持 `V2.1.0`。
- 新增 migration 0016–0018。
