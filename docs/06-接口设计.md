Snapshot 和 Delta 均支持可选 `parentSessionId`（1–1024 字符，不能等于当前 sessionId）；Delta 可只携带父子关系和原有基线校验字段。V2.3.3 统一会话主列表、项目时间线、项目/首页会话数及待归类口径。会话列表、项目时间线及待归类行包含直接活跃子记录数 `childCount`；详情包含 `parentConversation` 和 `childConversations`，用于独立完整记录间导航。搜索和项目/标签筛选可将子记录命中提升到活跃祖先主入口，不拼接消息或 Revision。

## 1. 认证、同源与统一响应

| 身份 | 认证方式 | 可访问范围 |
| --- | --- | --- |
| 公开 | 无 | `/healthz`、auth status/bootstrap/login、devices claim |
| Web 管理员 | `archive_session` HttpOnly Cookie | 除设备采集外的全部管理 API |
| 设备 | `Authorization: Bearer <token>` | `POST /captures`、`POST /captures/codex-lineage`、`POST /devices/heartbeat` |

Web 的 POST/PUT/PATCH/DELETE 除 Cookie 外要求 `Origin` 或 `Referer` 与 `APP_ORIGIN` 一致，并拒绝 cross-site。动态响应为 `Cache-Control: no-store`。

分页接口统一返回：

```json
{
  "items": [],
  "pagination": {
    "total": 13842,
    "limit": 100,
    "offset": 200,
    "hasMore": true
  }
}
```

常见状态：400 输入错误；401 Session/Token 无效；403 不同源；404 不存在；409 状态或唯一性冲突；410 暂存文件已删除；429 限流；503 任务未能入队或恢复维护中；500 未映射故障。非法 UUID 返回 400。恢复进入 restoring/rebuilding_search/verifying/recovery_required 时，除认证、恢复进度和系统状态等允许入口外返回503及 `Retry-After`。

## 4. 采集

`POST /captures` 是设备 Bearer 接口，接受完整/import `CaptureSnapshotV1` 或 append `IncrementalCaptureV1`。

主要限制：12 个 Provider；sessionId 1–1,024；title ≤2,048；adapterVersion 1–64；HTTP(S) URL ≤8,192；完整消息 1–100,000；append 消息 0–10,000；每消息 Segment 1–10,000；单 Segment 1–2,000,000；可选 `Idempotency-Key` ≤512。

归档新增或更新返回 201，重复/未变化返回 200。同一会话持续更新单份正文；回执的 `archiveMessageCount` 表示累计主正文条数，与本次采集的 `messageCount` 分开，客户端增量基线不能用累计条数代替。append 基线不匹配返回 409、`error=incremental_base_mismatch` 和 `requiresFullCapture=true`。解析失败 400 并尽量写失败 CaptureRun。归档成功后分类入队失败不回滚事实数据。

### 4.1 Codex 历史父子关系回填

`POST /api/v1/captures/codex-lineage` 使用 `Authorization: Bearer <设备 Token>` 和 `Content-Type: application/json`，请求体为：

```json
{
  "relations": [
    { "sessionId": "child-session-id", "parentSessionId": "parent-session-id" }
  ]
}
```

`relations` 必须有 1–500 条；每个 `sessionId`、`parentSessionId` 均为 1–1024 字符，两个 ID 不得相同。ID 是 Codex 原始外部 Session ID，不是数据库 Conversation UUID；无需 provider、消息、Revision 基线或 Idempotency-Key。有效设备 Token 认证失败返回 401，输入校验失败返回 400。

成功返回 200 和以下计数；循环关系计入 `rejected`，不会写入该关系：

```json
{ "updated": 1, "unchanged": 0, "notFound": 0, "rejected": 0 }
```

| 字段 | 含义 |
| --- | --- |
| `updated` | 已归档 Codex 记录的父 ID 本次成功更新数 |
| `unchanged` | 父 ID 已相同的记录数 |
| `notFound` | 对应子 Session 尚未归档的记录数，不创建新会话 |
| `rejected` | 关系校验后未写入的记录数，例如循环关系 |

该接口仅更新组织关系，不修改消息、Revision、内容哈希或 `deletedAt`，不会复活已删除记录；父记录可以晚到。实现与 Schema 位于 `apps/server/src/services/codex-history-lineage.ts`。代理按每批 500 条上传；全历史头部扫描和批次均成功后才保存完成标记，失败不会标记完成，可在后续扫描重试。

## 5. 会话累计正文、全文搜索、回收站和批量操作

### 5.1 列表与详情

`GET /conversations` 参数：

| 参数 | 规则 |
| --- | --- |
| `q` | 标题/完整正文，≤500；SQL 通配字符按字面 |
| `provider` | Provider 枚举 |

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/reports?limit=&offset=` | 默认 50，最大 200；分页 |
| GET | `/reports/:id` | 单份报告 |

| GET | `/analysis/runs?kind=&limit=&offset=` | kind weekly/monthly；limit 最大 100；分页 |
| POST | `/analysis/run` | body kind weekly/monthly；上一完整周期；queued/running/completed 复用已有任务，不重复入队或覆盖其状态；成功入队/复用 202，入队 null 标 failed 并返回 503 |

周期按实例IANA `TZ`，材料和月报引用周报均使用 `[windowStart, windowEnd)`。Report 响应包含邮件状态、attempt、发送时间和错误；没有报告编辑或删除接口。

`regenerate` 和 `generation` 的 `id` 必须为报告 UUID，均需 Web 登录。重新生成使用报告的 `periodStart/periodEnd`；延期到另一周或月执行也不改变窗口。同周期的 `analysisRuns` 行复用，`stats.generationId` 区分每轮生成，`stats.regeneratingReportId` 记录目标报告。并发请求复用 queued/running 任务。成功时正文及 completed 状态在同一事务内提交，报告 ID 保持不变；失败或原周期无可用材料时保留原正文。重新生成设置 `stats.sendEmail:false`，不创建邮件任务、不清除既有邮件发送记录。

有材料的 AI 报告正文校验五个章节及各章非空内容：周报为“本周主要讨论、关键变化、重要决定、尚未解决、下阶段关注点”，月报为“本月概览、项目演进、关键变化与决定、未解决问题、下月关注点”。拒绝省略号、TODO、待补充等占位输出；每轮最多三次正文质量尝试，耗尽后标记 failed。队列不再额外重试整轮质量失败；额度受限单独记录 `stats.stage:"deferred"`、`retryAt` 等信息，排队等待恢复，旧延迟任务不得提前绕过新的 `retryAt`。

`run` 包含 `id/status/error/stats/windowStart/windowEnd/createdAt/updatedAt/completedAt`。`stats.responseDiagnostics` 保存本轮至多 6 条响应诊断；`stats.previousGeneration` 保留上一轮的 generationId、状态、完成时间和至多 6 条诊断。每条诊断包含 `attempt`、`model`、`status`（accepted/rejected/request_failed）、`responseChars`、脱敏原始文本 `content`、`contentTruncated` 和 `recordedAt`；有返回值时另含 `responseId/requestId/finishReason/error/usage`，其中 usage 包含 promptTokens、completionTokens、totalTokens。超长文本仅保留首尾约 120,000 字符并标明截断。早期任务可能没有诊断，无法恢复当时未保存的原始响应。详情页每 2.5 秒轮询活动任务并在本轮完成后刷新正文，诊断默认折叠展示。

## 批量补采接口（V2.4.4）

- Web 登录与同源校验：`GET /api/v1/recapture/jobs` 查询近期队列；`POST /api/v1/recapture/jobs` 提交 `deviceId` 与 `conversationIds`（最多 500）或 `allIncomplete: true`；`POST /api/v1/recapture/jobs/:id` 提交 `action: pause | resume | cancel | retry_failed | retry_partial | retry_skipped | skip_current`。
- Chrome 设备令牌：`POST /api/v1/recapture/next` 领取或用 `leaseToken` 续租；`POST /api/v1/recapture/report` 提交 `jobId/itemId/leaseToken` 与 `captureId` 或 `outcome: failed | skipped | attention`。`skipped` 记录原因后继续队列，`attention` 暂停；`skip_current` 只允许跳过暂停队列中已尝试且当前未运行的条目。服务端验证入库回执所属设备、会话、完整快照和开始时间，不信任客户端自报“完整”。
- 同一设备至多一个运行或暂停队列；任务租约 120 秒，单次处理最长 10 分钟，意外中断最多自动尝试 3 次。删除或已完整归档的待处理条目自动跳过；过期任务上传不能恢复已删除会话。


### V2.4.10 首页组织统计响应收敛

`GET /dashboard/organization` 的 categoryStats 只返回最近12个七日内有活动的项目，排序为 latestActivityAt、growth7d、projectName；categoryTotals 保留完整数量，并增加 recentActiveCategoryCount。Web 不再用返回数组长度代表全部近期活跃项目数。会话搜索 total 与分页共用一次命中扫描，空尾页仍返回正确 total；搜索摘要继续返回真实 messageOrdinal。

### V2.4.11 中文搜索词条

列表响应和定位字段不变。纯中文单字、双字按词条等值命中；长短语求所有相邻双字的候选交集，再核对完整短语。词条散落在不同消息或位置只能进入候选，不能构成短语命中。英文和混合查询保留既有语义。总数与分页共享匹配结果。

### V2.4.12 搜索内部写入与短语验证

接口响应和定位字段不变。长中文短语仅在词条交集候选的实际修订分块中核对，首个命中即停，不跨分块拼接；标题、历史修订及父会话命中语义保留。追加采集只维护新增消息引入的词条，元数据更新不触及搜索索引；完整改写与索引恢复仍做完整校准。英文与中英混合查询维持现有分块检索入口。

V2.4.12 的长中文短语在候选修订约束内采用字面 LIKE，允许 PostgreSQL 组合既有正文 trigram 与修订索引，首个命中即停；摘要复用相同核对逻辑。单字、双字不走这条正文 trigram 路径。
